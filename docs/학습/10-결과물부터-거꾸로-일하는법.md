# 출력물 역추적법 — 현업에 처음 투입됐을 때 어디부터 볼까

> ⚠️ **이 문서는 "사람에게 묻는 법"이다.** 물어볼 사람이 없거나, 묻기 전에 스스로 알아내야 하면 **`12-화면값이-어느-테이블인지-찾기.md`** 를 먼저 본다. 둘은 짝이다 — **코드로 먼저 훑어 ❓ 를 줄이고, 남은 것만 사람에게 묻는다.**
>
> **질문**: 용어를 하나도 모르는데, 큰 숲을 보고 현업이 원하는 걸 만들 수 있을까?
> **답**: 만들 수 있다. 단, **보는 순서**를 바꿔야 한다.
>
> 이 문서는 *"오늘 회사에 투입됐다"* 를 가정하고, **첫날부터 3일 안에 전체 그림을 잡는 방법**을 다룬다.

## 0. 결론부터

```
❌ 1번 화면부터 순서대로 본다          →  용어의 늪. 3일 뒤에도 그림이 안 그려진다
✅ 마지막 출력물부터 거꾸로 따라간다   →  하루 만에 지도가 그려진다
```

이 프로젝트로 치면 **F3 출하성적서(종이 한 장)를 먼저 손에 쥐고**, 그 종이의 칸을 하나씩 짚으며 *"이 값은 어디서 오나?"* 를 되짚는다.

> 💡 이건 새로운 얘기가 아니다. **이 프로젝트의 계획서에 이미 그렇게 적혀 있다:**
> > *"CoA는 MES의 **terminal output**이라, 이걸 제대로 뽑으려면 Spec→검사실적→Lot 역참조 체인이 전부 필요하다"* (master-plan §1)
> > *"이 문서 1장이 스프린트의 결과물이다. **이걸 먼저 그려야 F1/F2가 무엇을 저장해야 하는지 역산된다.**"* (§3)

## 1. 🟢 왜 거꾸로 보나 — 김밥 이야기

### 김밥 한 줄을 받아들었다고 하자

🟢 **김밥을 한 입 베어물고 되짚는다.**

```
김밥 한 줄
  ├─ 밥      ← 쌀통에서 씻어서 지은 것
  ├─ 단무지  ← 사온 것
  ├─ 시금치  ← 데쳐서 무친 것 (준비가 필요!)
  ├─ 계란    ← 부쳐서 썬 것 (준비가 필요!)
  └─ 김      ← 사온 것
```

**되짚기가 끝나면 저절로 두 가지가 손에 들어온다:**
1. **재료 목록** (뭘 사야 하나)
2. **준비 순서** (시금치는 데쳐야 하고, 계란은 부쳐야 한다)

### 반대로 하면?

🟢 **냉장고를 열고 재료를 하나씩 공부한다.**

> *"이건 시금치… 데치면 나물이 되고 볶으면… 아 이건 계란, 삶을 수도 부칠 수도…"*

**끝이 없다.** 냉장고에 재료가 100개면 100개를 다 공부해야 한다. 그리고 **김밥에 안 들어가는 재료까지** 공부하게 된다.

> 😖 **이게 "1번 화면부터 순서대로 보기"다.**

## 2. 이 프로젝트에 대입하면

### ❌ 순서대로 봤을 때 (F1부터)

F1 화면을 연다. 이런 게 보인다.

| 순번 | 항목코드 | 항목명 | 단위 | **판정** | **하한** | **상한** | 소수 |
|---|---|---|---|---|---|---|---|
| 1 | TS | 인장강도 | MPa | 범위형 | 400 | 500 | 1 |

머릿속:
> *"판정방식이 뭐지? 범위형·상한형·하한형은 무슨 차이지? LSL이 뭐고 USL이 뭐지? 소수자리는 왜 있지? 순번은 왜 필요하지?"*

**질문이 7개 생겼는데 답을 알아도 "그래서 이게 왜 필요한지"는 여전히 모른다.**

### ✅ 거꾸로 봤을 때 (F3부터)

성적서 종이를 먼저 본다.

```
┌────────────────────────────────────────────────┐
│              출 하 성 적 서 (CoA)               │
├──────────┬──────────────┬──────────────────────┤
│성적서번호│ 발행일자      │ 고객사                │
│CoA-...001│ 2026-09-04   │ (주)대한기계          │
├──────────┼──────────────┼──────────────────────┤
│ 품목     │ Lot No.      │ 출하수량              │
│ 스틸브라켓│ LOT-...001   │ 100 EA               │
├───┬──────┬──────┬───────┬────────┬─────────────┤
│No │검사항목│단위 │ 규격  │ 측정값 │ 판정        │
│ 1 │인장강도│ MPa │400~500│ 452.0  │ PASS        │
│ 2 │경도   │ HRC │ 55~62 │  58    │ PASS        │
├───┴──────┴─────┴────────┴────────┴─────────────┤
│ 종합판정 : PASS                                 │
│ 발행자 : 홍길동                          (인)   │
└────────────────────────────────────────────────┘
```

**칸마다 "이 값 어디서 와?" 만 물으면 된다.**

| 칸 | 이 값 어디서? | 그래서 발견한 것 |
|---|---|---|
| 규격 `400~500` | *"품질팀이 미리 정해둬요"* | → **F1 화면이 필요하구나** |
| 측정값 `452.0` | *"검사원이 재서 넣어요"* | → **F2 화면이 필요하구나** |
| 판정 `PASS` | *"규격이랑 비교해서 자동으로요"* | → **자동 판정 로직이 필요하구나** |
| 종합판정 `PASS` | *"하나라도 떨어지면 FAIL이요"* | → **합치는 규칙이 있구나** |
| Lot No. | *"만든 물건 묶음 번호요"* | → **Lot이라는 단위가 있구나** |
| 성적서번호 | *"발행할 때 자동으로 따요"* | → **채번이 필요하구나** |
| 고객사·출하수량 | *"발행할 때 직접 쳐요"* | → **입력 화면이 필요하구나** |

> 🟢 **7개 칸을 물어보니 프로그램 전체가 나왔다.** 그리고 **왜 필요한지를 알면서** 알게 됐다.

### 두 방법의 결정적 차이

| | 순서대로 (F1→) | 거꾸로 (F3→) |
|---|---|---|
| **배우는 계기** | *"나중에 필요하겠지"* | **"지금 이 칸 때문에 필요해"** |
| **끝을 아는가** | 모름. 불안 | **성적서 칸을 다 짚으면 끝** |
| **중요도** | 다 똑같아 보임 | **성적서에 찍히면 중요, 아니면 나중** |
| **현업 대화** | *"MES가 뭔가요?"* | **"이 칸은 누가 채워요?"** |

## 3. 실전 절차 — Day 0 부터

### 📅 Day 0, 오전 (30분) — **실물을 손에 넣는다**

🖱️ **할 일**: 지금 쓰고 있는 **출력물 실물**을 한 장 구한다.

- 종이든, 엑셀이든, 캡처든 상관없다
- 이상적인 건 **최근에 실제로 고객사에 나간 것**

😖 **없다고 하면?** 그게 **첫 번째 발견**이다.
> *"아직 양식이 없다"* = 이 프로젝트의 첫 번째 결정사항이 **"양식 확정"** 이라는 뜻.
> 실제로 이 프로젝트도 R1 리스크가 *"CoA 최종 양식 미확정 시 전체 역산 불가"* 였다.

🟢 **김밥을 만들라는데 어떤 김밥인지 안 알려준 것**과 같다. 참치김밥인지 야채김밥인지부터 정해야 재료를 산다.

### 📅 Day 1 — **실물을 들고 물어본다**

🖱️ **할 일**: 종이를 **들고 가서** 현업 옆에 앉는다.

#### ❌ 이렇게 묻지 마라

> *"MES가 뭔가요?"*
> *"품질 관리 프로세스를 설명해주시겠어요?"*

😖 **1시간짜리 강의가 시작되고, 끝나면 하나도 안 남는다.** 상대도 어디부터 설명할지 몰라 막막하다.

#### ✅ 이렇게 물어라

> (종이의 ⑧번 칸을 손가락으로 짚으며)
> **"이 '400~500'은 누가 정해요?"**

😀 **30초 안에 정확한 답이 온다.**
> *"아 그거 품질팀에서 품목 등록할 때 넣어요. 고객사 도면 보고요."*

🟢 **외국 식당에서 메뉴를 모를 때**와 같다.
- ❌ *"이 나라 음식 문화를 설명해주세요"* → 막막
- ✅ (사진 가리키며) *"이거 뭐예요?"* → 바로 답

#### 막힐 때 쓰는 만능 질문 3개

| 질문 | 알아내는 것 |
|---|---|
| **"이거 없으면 무슨 일이 생겨요?"** | 진짜 중요한지 (없어도 되면 안 만들어도 된다) |
| **"이 값이 틀리면 누가 곤란해져요?"** | 책임 소재 = 검증을 얼마나 빡세게 할지 |
| **"지금은 어떻게 하고 계세요?"** | 현행 방식 = 최소한 이것보단 나아야 한다 |

💡 **세 번째가 특히 강력하다.** *"엑셀로 손으로 쳐요"* 라는 답이 나오면, **그 엑셀을 달라고 하면 된다.** 그게 요구사항 명세서다.

### 📅 Day 2 — **역순 지도를 그린다**

물어본 답을 이어붙이면 **지도가 저절로 나온다.**

```
        [성적서 한 장]  ← 최종 출력물
              ↑
    ┌─────────┴─────────┐
    │                   │
 발행 입력           검사 결과
 (고객사·수량)          ↑
                   ┌────┴────┐
                   │         │
                측정값      규격
              (검사원 입력) (품질팀 등록)
```

이걸 **왼→오른쪽으로 뒤집으면** 그게 **만드는 순서**다.

```
규격 등록  →  검사 입력  →  성적서 발행
  (F1)        (F2)          (F3)
```

> 🟢 **집 짓기와 같다.** 완성된 집 사진을 먼저 보고 설계하지만, **짓기는 기초부터** 한다.
> **보는 순서와 만드는 순서는 반대다.** 이걸 헷갈리면 안 된다.

| | 순서 |
|---|---|
| **파악(보는) 순서** | F3 → F2 → F1 (거꾸로) |
| **제작(만드는) 순서** | F1 → F2 → F3 (순방향) |

## 4. 😖 순서대로 봤을 때 겪는 고통 5가지

### ① 용어의 늪 — 하루 종일 단어만 외운다

F1을 열면 모르는 단어가 7개 나온다. 그걸 찾아보면 그 설명에 또 모르는 단어가 나온다.

🟢 **사전을 A부터 읽는 것**과 같다. `가나다` 를 다 외워도 **문장은 못 만든다.**

### ② 중요도를 모른다 — 안 쓰는 것도 똑같이 공부한다

F1에는 `targetVal`(목표치) 이라는 칸이 있다. **이 프로젝트에서는 안 쓴다.**
순서대로 보면 이걸 `lsl`(하한, 핵심)과 **똑같이 중요하게** 공부한다.

😖 거꾸로 봤다면? **성적서에 `targetVal` 이 안 찍힌다** → 바로 알았다.

### ③ 끝을 모른다 — 불안하다

> *"이걸 다 알아야 하나? 얼마나 남았지?"*

😖 이 불안이 **가장 큰 시간 낭비**다. 실제로는 안 해도 될 공부를 계속하게 된다.

😀 거꾸로 보면 **끝이 명확하다** — 성적서 칸 12개를 다 짚으면 끝이다.

### ④ 현업과 대화가 안 된다

3일째인데 *"그래서 뭘 만드는 거예요?"* 라는 질문에 답을 못 한다.
😖 **현업은 "이 사람 아직 모르는구나"** 라고 판단하고, 그때부터 설명을 덜 해준다.

### ⑤ 버려질 걸 공부한다

이 프로젝트에서 **F4 품질피벗은 P1(후순위)** 이다. 일정이 밀렸으면 **안 만들었을 수도** 있다.
😖 순서대로 봤으면 F4를 공부하는 데 하루를 썼을 수도 있다.

😀 거꾸로 보면? **성적서를 만드는 데 F4는 필요 없다.** 바로 알 수 있다.

## 6. 이걸 뭐라고 부르나

준의 규칙집(`CLAUDE.md`)에 이미 있다. **IPO 개발법 — Output First.**

```
🎯 Output  : 성적서 한 장          ← 이걸 먼저 못박는다
📥 Input   : 규격 + 측정값          ← Output 에서 역산된다
⚙️ Process : 규격과 비교해 판정      ← 그다음에 정해진다
```

> **"Output을 한 문장으로 못 쓰면 착수 금지"** — 이 규칙이 바로 이 문서의 요약이다.
>
> 🟢 **뭘 만들지 모르면서 재료부터 사는 것**을 막는 규칙이다.

### 다른 도메인에도 그대로 쓴다

| 도메인 | terminal output (먼저 볼 것) |
|---|---|
| 회계 | **재무제표 / 세금계산서** |
| 인사 | **급여명세서** |
| 물류 | **거래명세서 / 송장** |
| 병원 | **진료비 계산서 / 처방전** |
| 학교 | **성적표 / 생활기록부** |

🟢 **거의 모든 업무 시스템에는 "마지막에 나가는 종이"가 있다.** 그걸 먼저 찾으면 된다.

**찾는 법**: *"이 시스템이 없으면 회사가 어떤 종이를 못 만드나요?"* 라고 물으면 나온다.

## 7. 그래서 지금 이 프로젝트는 어떻게 볼까

준이 *"F3부터 보겠다"* 고 한 판단이 맞다. 순서는 이렇다.

```
1️⃣  F3 성적서 발행    ← 여기부터. "무엇을 만드는가"
       ↓ "이 칸 어디서 와?"
2️⃣  F2 검사실적       ← 측정값·판정의 출처
       ↓ "규격은 어디서 와?"
3️⃣  F1 품질규격       ← 기준의 출처
       ↓ (곁가지)
4️⃣  F4 품질피벗       ← 성적서에 안 쓰인다. 관리자 조회용
5️⃣  F0 컴포넌트 검증  ← 개발자용. 현업은 안 본다
```

> `docs/32-화면-눌러보기-대본.md` 는 **만드는 순서(F1→F2→F3)** 로 되어 있다. 이미 다 만들어진 걸 **동작 순서대로** 체험하는 문서라서다.
>
> **처음 파악할 때는 이 문서 순서(F3→F2→F1)**, **직접 해볼 때는 실습 문서 순서**를 쓰면 된다. 둘은 목적이 다르다.

## 8. 마지막 — 용어를 몰라도 되나?

**된다. 오히려 유리한 면도 있다.**

😖 **용어를 알면 "안다고 착각"한다.**
> *"아, Lot이요? 알죠."* → 사실은 이 회사에서 Lot을 어떻게 끊는지 모른다.
> 회사마다 다르다. 어떤 데는 하루 단위, 어떤 데는 오븐 한 판 단위다.

😀 **모르면 물어본다.** 그리고 **현업은 자기 일을 설명하는 걸 좋아한다.**

> 🟢 **길을 물어보는 것과 같다.** 아는 척하고 헤매는 것보다, 물어보고 5분 만에 가는 게 낫다.
> 물어본다고 무시당하지 않는다. **아는 척하다 틀린 걸 만들어야** 무시당한다.
