# "남은 것" 한 줄 읽는 법

> 이 문장 하나를 해부한다.
>
> > **남은 것: F4 품질피벗 / M4 threshold 95 복원·재측정 / carry item 3건(F3 인쇄 DoD · INSP_ITEM_REQUIRED 판단 · Lot 전환 현상)**
>
> 단어는 하나씩 보면 알겠는데 **이어 놓으니 안 읽히는** 이유가 있다. 그 이유부터 짚는다.

## 0. 왜 안 읽히나 — 당신 탓이 아니다

이 한 줄에는 **성격이 완전히 다른 세 가지**가 섞여 있다.

🟢 **냉장고 메모지**에 이렇게 적혀 있다고 생각해보자.

```
살 것: 우유 / 체중계 배터리 갈기 / 지난주 깨진 접시 치우기
```

- **우유** = 아직 안 산 것 → **새로 사와야 함**
- **체중계 배터리** = 물건은 있는데 **측정 도구가 죽어 있음** → 재려면 먼저 살려야 함
- **깨진 접시** = 이미 벌어진 일인데 **"나중에 치우자"고 미뤄둔 것**

셋 다 "할 일"이지만 **종류가 다르다.** 우유는 없어서 사는 거고, 배터리는 재려고 가는 거고, 접시는 미뤄둔 빚이다.

**우리 문장도 똑같다.**

| 항목 | 냉장고로 치면 | 종류 |
|---|---|---|
| **F4 품질피벗** | 우유 | 🟦 **아직 안 만든 기능** |
| **M4 threshold 복원·재측정** | 체중계 배터리 | 🟨 **검사 도구 손보기** |
| **carry item 3건** | 깨진 접시 | 🟥 **미뤄둔 빚** |

> 🟢 **안 읽혔던 이유**: 셋을 같은 종류로 읽으려니까 말이 안 됐던 거다. **"/" 로 구분된 건 사실 다른 서랍**이다.

## 1. 🟦 F4 품질피벗 — 아직 안 만든 것

### 생활 예제

🟢 **반 전체 성적을 한 표로 보는 화면.**

성적표(F3)는 학생 한 명당 한 장이다. 그런데 담임이 이렇게 묻는다:
*"지난주 애들 수학 점수 다 비슷했어? 유독 낮은 애 있었나?"*

이건 성적표 30장을 넘겨보며 답할 수 없다. **한 표로 펼쳐놔야** 한다.

```
        수학  국어  영어      ← 가로 = 과목
철수     75    80    90
영희     90    85    70       ← 세로 = 학생
민수     60    95    85
```

### 왜 "피벗"이라고 부르나

서버는 이렇게 **세로로 한 줄씩** 준다: `철수-수학-75`, `철수-국어-80`, `영희-수학-90`…
이걸 **가로 표로 눕히는 것**을 피벗(pivot, 돌리다)이라고 한다. 엑셀 피벗테이블과 같은 말이다.

### 알면 뭐가 좋은가

**"남은 게 뭔지"의 크기를 알 수 있다.** "화면 하나 더 만들면 끝"인지, "설계부터 다시"인지가 완전히 다르다.

관리자가 *"언제 끝나?"* 라고 물을 때 답할 수 있다 —
> *"화면 4개는 됐고, 마지막 1개는 표 칸 개수가 매번 바뀌는 화면이라 하루쯤 걸립니다."*

### 모르면 어떤 고통인가

😖 **일정을 못 낸다.** "남은 것: F4"만 보고는 그게 30분짜리인지 3일짜리인지 알 수 없다.
그래서 *"거의 다 됐어요"* 라고 말했다가 일주일이 더 걸리는 일이 생긴다.

## 2. 🟨 M4 threshold 95 복원·재측정 — 검사 도구 손보기

여기가 제일 안 읽혔을 부분이다. 세 단어가 붙어 있다: **M4** / **threshold** / **복원·재측정**.

### 하나씩

| 단어 | 🟢 생활 예제 | 🔵 실제 |
|---|---|---|
| **M4** | **진급 시험 과목 이름** | 품질 지표 이름. "설계서에 적은 대로 코드를 짰나"를 재는 점수 |
| **threshold** | **합격선** (60점) | 통과 기준 점수 |
| **복원** | 낮춰놨던 합격선을 **원래대로** | 95로 되돌리기 |
| **재측정** | **다시 시험 보기** | 다시 점수 매기기 |

### 이어서 읽으면

> **"낮춰놨던 합격선(95점)을 원래대로 되돌리고, 시험을 다시 본다"**

### 왜 낮춰놨었나 — 여기가 이야기의 핵심

🟢 이런 일이 있었다.

M4는 **"설계서대로 코드를 짰나"** 를 재는 시험이다. 그런데 우리는 **코드를 짜기 전에** 그 시험을 봤다.

> 😵 **답안지를 안 낸 상태에서 채점을 한 것이다.**

9번 봤는데 9번 다 떨어졌다. 당연했다. 그래서 **합격선을 잠깐 0점으로 내려놓고** 다음 단계로 넘어갔다 — 대신 **"코드가 생기면 반드시 95로 되돌린다"** 고 기록을 남겼다.

코드를 다 만들고 다시 재니 **100점**이 나왔다. 그리고 그 과정에서 **진짜 버그 3개**를 잡았다.

### 왜 "복원"이라는 말을 쓰나

🟢 **원래 자리로 돌려놓는다**는 뜻이다. 임시로 치워놨던 걸 제자리에.

**임시 조치에는 반드시 "언제 되돌릴지"가 붙어야 한다.** 안 그러면 임시가 영원이 된다.

### 알면 뭐가 좋은가

**"기준을 왜 낮췄는지"와 "언제 되돌릴지"를 아는 사람이 된다.**

이건 신뢰의 문제다. 나중에 누가 프로젝트를 보고 *"어라, 이 팀은 합격선이 0이네? 대충 했구나"* 라고 오해하지 않는다.

### 모르면 어떤 고통인가

😖 **두 가지 고통이 있다.**

1. **아무도 안 되돌린다.** "잠깐만 낮추자"가 6개월 뒤에도 그대로 남는다. 그 프로젝트는 **검사 장치가 꺼진 채로 굴러간다.**
2. **나중에 누가 발견하고 신뢰를 잃는다.** *"기준을 0으로 해놓고 통과했다고 한 거였네?"*

🟢 **체중계 눈금을 5kg 빼놓고 "살 빠졌다"고 하는 것**과 같다. 잠깐 그럴 수는 있는데, **왜 그랬고 언제 되돌릴지를 안 적어두면 사기**가 된다.

## 3. 🟥 carry item — 미뤄둔 빚

### 이 단어가 제일 중요하다

**carry item** = *carry over*(다음으로 넘기다) 에서 온 말. **"이번엔 못 했으니 다음으로 넘김"** 이라고 적어둔 항목.

🟢 **방학 숙제 중 안 한 걸 개학 전날 목록으로 적어두는 것**이다.

### 여기가 핵심 — "미룬 것"과 "잊은 것"은 하늘과 땅 차이다

| | 미룬 것 (carry item) | 잊은 것 |
|---|---|---|
| 기록 | **있다** | 없다 |
| 나중에 | 목록 보고 처리 | **사고로 발견** |
| 신뢰 | *"알고 미뤘구나"* | *"이것도 몰랐구나"* |

😖 **똑같이 "안 한 것"인데 결과가 완전히 다르다.**

🟢 **숙제를 안 해간 두 학생**을 생각해보자.
- A: *"선생님, 3번 4번은 못 풀었습니다. 내일까지 해오겠습니다."*
- B: 아무 말 안 하고 냈다가 걸림

**한 일의 양은 똑같다.** 그런데 A는 성실한 학생이고 B는 거짓말한 학생이 된다.

> **이게 carry item 을 적는 유일한 이유다.** 안 한 걸 없던 일로 만들지 않기 위해서.

## 4. carry item 3건 하나씩

### ① F3 인쇄 DoD

**DoD** = Definition of Done = **"어디까지 하면 끝인가"의 합의**

🟢 **"방 청소 다 했어?"** 라고 물었을 때, 엄마가 생각하는 "다 함"과 내가 생각하는 "다 함"이 다르면 싸움이 난다.
그래서 **미리 정해둔다**: *"바닥 쓸고 + 책상 정리하고 + 이불 개면 끝"*

**여기서의 DoD**: *"성적서가 2페이지를 넘어갈 때, **2쪽 맨 위에도 표 제목이 다시 나오는지** 눈으로 확인한다"*

🟢 왜 이게 중요한가: 2쪽부터 열 제목이 없으면 *"이 숫자가 측정값인지 규격인지"* 를 알 수 없는 종이가 고객사에 간다.

**왜 못 끝냈나**: 검사항목을 30개까지 늘려 1.32쪽까지 만들었는데, **인쇄 미리보기 창을 띄우는 순간 자동화가 멈춰서** 제가 눈으로 볼 수가 없었다. **사람이 [인쇄] 버튼을 한 번 눌러야** 끝난다.

**알면**: "끝났다"고 말할 수 있는 조건이 명확하다.
**모르면**: 😖 *"됐다면서요?"* → *"거의 됐어요"* → *"거의가 뭔데요"* 의 무한 반복.

---

### ② `INSP_ITEM_REQUIRED` 판단

**대문자에 밑줄 친 건 에러 코드 이름**이다. `INSP_ITEM_REQUIRED` = *"검사항목(코드)이 필수인데 비었다"*

🟢 **에러 코드는 "이름표"** 다. 병원에서 *"환자분, 002번 상태입니다"* 라고 하면 의사끼리는 통한다.

**문제였던 것**: 항목코드를 **비워두고** 저장했더니 이런 메시지가 떴다.

> 항목코드는 **필수**입니다. `[INSP_ITEM_DUPLICATED]`
>                                       ↑ **"중복"** 이라는 이름표

🟢 **"이름을 안 썼어요"라고 말하면서 '이름 중복' 도장을 찍은 것**이다. 메시지는 맞는데 이름표가 틀렸다.

**"판단"이라고 쓴 이유**: 이건 **그냥 고치면 되는 게 아니라 정해야 하는 것**이었다.
새 이름표를 하나 더 만들면 관리할 이름표가 28개 → 29개로 늘어난다. *"메시지가 맞으니 그냥 두자"* 도 선택지였다.
→ 결국 **만들기로 정했다.** 옆 칸(항목명)은 이미 자기 이름표를 쓰고 있어서 **항목코드만 남의 것을 빌려 쓰는 게 이상**했기 때문이다.

**알면**: 😀 **"그냥 하면 되는 일"과 "정해야 하는 일"을 구분**할 수 있다. 후자는 남에게 물어야 한다.
**모르면**: 😖 혼자 정해버리고, 나중에 *"누가 이렇게 하라고 했어요?"* 를 듣는다.

---

### ③ Lot 전환 현상

🟢 **"화면에서 고른 게 저절로 다른 걸로 바뀐 적이 딱 한 번 있었다."**
다시 해보니 안 그런다. **원인을 못 찾았다.**

**"현상"이라는 단어를 쓴 이유가 있다.** *"버그"* 라고 쓰면 *"어디가 잘못됐는지 안다"* 는 뜻이 된다. 모르는데 안다고 쓰면 안 된다.

🟢 **자동차에서 딱 한 번 이상한 소리가 났는데 정비소에서는 안 나는 것**과 같다. 정비사가 *"고쳤습니다"* 라고 하면 거짓말이다. 정직한 답은 **"1회 발생, 재현 안 됨, 원인 미상"** 이라고 적어두는 것이다.

**그래서 코드를 안 건드렸다.** 원인을 모르는데 아무 데나 고치면 **멀쩡한 걸 망가뜨릴 뿐**이다.

**알면**: 😀 **"모른다"를 기록하는 것도 자산**이라는 걸 안다. 나중에 또 나면 *"아, 그때 그거"* 가 되고 두 번째부터는 단서가 생긴다.
**모르면**: 😖 **조용히 덮는다.** 그리고 6개월 뒤 고객 앞에서 재발한다. 그때는 **아무 기록도 없어서 처음부터 다시** 찾아야 한다.

## 5. 그래서 왜 이렇게 압축해서 쓰나

🟢 **냉장고 메모에 "우유"라고 쓰지, "냉장고에 우유가 떨어졌으니 마트에 가서 1리터짜리 서울우유를 사오기"라고 안 쓴다.**

이유는 셋이다.

| 이유 | 설명 |
|---|---|
| **매일 봐야 하니까** | 풀어 쓰면 3페이지가 된다. 3페이지짜리는 아무도 매일 안 본다 |
| **검색되니까** | `INSP_ITEM_REQUIRED` 를 그대로 쓰면 **코드와 문서에서 그 단어로 바로 찾을 수 있다.** "검사항목 필수 오류"라고 풀어 쓰면 못 찾는다 |
| **애매함이 없으니까** | "M4"는 딱 하나를 가리킨다. "그 품질 점수"는 여러 개일 수 있다 |

### 하지만 압축에는 값이 있다

😖 **읽는 사람이 풀 수 없으면 압축이 아니라 암호다.**

그래서 이런 규칙이 필요하다:

> **압축해서 쓰되, 그 옆에 "푸는 열쇠"를 둔다.**
> 이 프로젝트의 열쇠 = `31-용어사전-생활예제.md` + `../HANDOFF.md` + 지금 이 문서

## 6. 이런 줄을 만나면 이렇게 읽어라 — 3단계

### 1단계 — `/` 로 자른다

```
남은 것:  F4 품질피벗  /  M4 threshold 95 복원·재측정  /  carry item 3건(...)
          ①              ②                              ③
```

### 2단계 — 각 조각이 **어느 서랍**인지 본다

| 물어볼 것 | 서랍 |
|---|---|
| "**아직 안 만든** 건가?" | 🟦 기능 |
| "**재는 도구**에 관한 건가?" | 🟨 품질 장치 |
| "**이미 알고 미뤄둔** 건가?" | 🟥 빚 |

### 3단계 — 각 조각에 이 두 질문을 던진다

```
① 누가 해야 하나?     ← 나? 다른 사람? 결정권자?
② 언제까지 해야 하나?  ← 지금? 다음 스프린트? 언젠가?
```

우리 문장에 적용하면:

| 조각 | 서랍 | 누가 | 언제 |
|---|---|---|---|
| F4 품질피벗 | 🟦 기능 | 개발자 | 이번 스프린트 |
| M4 threshold 복원 | 🟨 장치 | 개발자 | 코드 다 만든 직후 |
| F3 인쇄 DoD | 🟥 빚 | **사람이 직접 눌러야** | 배포 전 |
| `INSP_ITEM_REQUIRED` | 🟥 빚 | **결정권자** | 다음 손볼 때 |
| Lot 전환 현상 | 🟥 빚 | 아무도 (관찰만) | 재발하면 |

> 🟢 **이 표가 만들어지는 순간 "남은 것" 한 줄이 읽힌다.**
> 안 읽혔던 이유는 **누가·언제가 전부 다른 다섯 개를 한 줄에 뭉쳐놨기** 때문이다.

## 7. 총정리 — 알면 좋은 것 / 모르면 겪는 고통

### 😀 알면

| | |
|---|---|
| **크기를 안다** | "남은 게 하루짜리인지 일주일짜리인지" |
| **말을 할 수 있다** | 관리자가 *"언제 끝나?"* 물을 때 근거 있게 답한다 |
| **정직해진다** | "안 한 것"을 "없던 일"로 만들지 않는다 |
| **혼자 안 정한다** | "판단"이라고 적힌 건 물어봐야 할 것이라는 신호다 |
| **모르는 걸 안다고 안 한다** | "현상"과 "버그"를 구분해서 쓴다 |

### 😖 모르면

| | 어떤 일이 생기나 |
|---|---|
| **일정이 무너진다** | *"거의 다 됐어요"* → 일주일 더 |
| **임시가 영원이 된다** | 낮춰둔 기준을 아무도 안 되돌린다 |
| **빚이 사고가 된다** | 미뤄둔 걸 잊고, 고객 앞에서 터진다 |
| **신뢰를 잃는다** | *"이것도 안 됐네요?"* — 몰라서가 아니라 **말을 안 해서** |
| **같은 문제를 두 번 찾는다** | "원인 미상"을 안 적어두면 재발 시 처음부터 |

---

## 8. 다음에 당신이 이런 줄을 쓸 때

관리자에게 보고할 때 이 형식을 쓰면 좋다. **종류를 섞지 말고 나눠 쓴다.**

```
✅ 완료 : F0 공통 · F1 규격 · F2 검사 · F3 성적서 · F4 피벗 (5/5)

🔜 남음 : [기능]   없음
          [검사]   없음
          [빚]     ① 성적서 2쪽 인쇄 확인 — 사람이 눌러봐야 함 (배포 전)
                   ② 자바 백엔드 — Sprint-2
```

🟢 **"남은 것" 한 줄에 다 밀어 넣지 말고, 서랍별로 나눠서 준다.** 받는 사람이 훨씬 편하다.
그리고 **빚에는 "누가·언제"를 꼭 붙인다.** 안 붙이면 그건 빚이 아니라 그냥 소원이다.
