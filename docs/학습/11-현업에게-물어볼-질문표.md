## 쓰는 법 — 3가지만 지킨다

| | 규칙 | 왜 |
|---|---|---|
| ① | **혼자 미리 번호를 매긴다** | 현업 앞에서 매기면 5분이 날아가고 *"준비 안 해왔네"* 로 읽힌다 |
| ② | **❓ 를 남긴 채로 들고 간다** | 다 채워 가면 *"네네 맞아요"* 로 끝난다. **빈칸이 있어야 말이 나온다** |
| ③ | **답은 그 자리에서 적는다** | 30분 뒤면 절반을 잊는다. 같은 걸 두 번 물으면 신뢰가 깎인다 |
| ④ | **코드로 먼저 30분 훑고 온다** | ❓ 가 줄어든다. `12-화면값이-어느-테이블인지-찾기.md` 참조 |

> 🟢 **식당에서 메뉴를 미리 고른 뒤 직원을 부르는 것**과 같다. 직원 세워놓고 메뉴판을 처음부터 읽으면 서로 피곤하다.

### 📄 화면 말고 종이로

노트북은 **화면을 상대 쪽으로 돌려야** 하고 손가락으로 짚기도 애매하다.
**A4 한 장**이면 나란히 앉아 **같은 칸을 동시에 짚는다.** 상대가 볼펜으로 표시해주기도 한다.

### 물어볼 순서 (권장)

**가운데(⑫⑬⑭)부터.** 이 세 칸이 시스템의 심장이다.

```
1️⃣ ⑬ 측정값   ← 이 프로그램이 진짜로 다루는 데이터
2️⃣ ⑫ 규격     ← 측정값을 판단하는 기준
3️⃣ ⑭ 판정     ← 앞의 둘로 어떻게 만들어지나
4️⃣ ⑮ 종합판정 ← 여러 개를 어떻게 합치나
5️⃣ ⑥ Lot No.  ← 이 모든 게 무엇에 붙어 있나
   ↓
나머지(①②③④⑤⑦⑧⑨⑩⑪⑯)는 위 5개가 풀리면 대부분 저절로 풀린다
```

💡 **왜 가운데부터인가**: ①②③ 같은 헤더는 *"발행할 때 그냥 넣는 값"* 이라 답이 짧다.
⑫⑬⑭ 는 **업무 규칙**이 들어 있어서, 여기서 이야기가 터진다.

## 2부 — 막힐 때 쓰는 만능 질문 3개

어느 칸에서든 이 셋을 던지면 뭔가 나온다.

| 질문 | 알아내는 것 | 🟢 왜 |
|---|---|---|
| **"이거 없으면 무슨 일이 생겨요?"** | 진짜 중요한지 | 없어도 되면 **안 만들어도 된다** |
| **"이 값이 틀리면 누가 곤란해져요?"** | 책임 소재 | 곤란한 사람이 클수록 **검증을 빡세게** |
| **"지금은 어떻게 하고 계세요?"** | 현행 방식 | 최소한 **이것보단 나아야** 한다 |

### 세 번째가 제일 강력하다

> *"지금은 엑셀로 손으로 쳐요."*

😀 이 답이 나오면 **그 엑셀을 달라고 하면 된다.** 그게 요구사항 명세서다.
사람들이 실제로 쓰는 양식에는 **말로 설명 안 되는 규칙**이 다 들어 있다.

## 4부 — 하면 안 되는 것

| ❌ | 왜 안 되나 |
|---|---|
| **현업 앞에서 번호 매기기** | 시간 낭비 + *"준비 안 해왔네"* |
| **다 채워서 확인만 받기** | *"네네 맞아요"* 로 끝나고 **틀린 것도 넘어간다** |
| **"MES가 뭔가요?" 같은 큰 질문** | 1시간 강의, 하나도 안 남음 |
| **답을 나중에 정리하기** | 30분 뒤 절반을 잊음 → **같은 걸 두 번 묻게 됨** |
| **아는 척하기** | 틀린 걸 만들고 나서야 들통난다. 그때가 제일 비싸다 |
| **한 번에 다 물어보기** | 상대가 지친다. **5~7개씩 끊는다** |

> 🟢 **길을 물을 때와 같다.** 아는 척하고 헤매느니 물어보고 5분 만에 가는 게 낫다.
> **물어본다고 무시당하지 않는다. 아는 척하다 틀린 걸 만들어야** 무시당한다.
