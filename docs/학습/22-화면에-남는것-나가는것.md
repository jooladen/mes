# 화면과 로직 분리 — 실무 Q&A

> *"화면과 로직을 분리한다면 화면에 로직이 하나도 없어야 하는 것 아닌가?"*
> 2026-09-06 실습 중 나온 질문에서 출발한다. 답은 **"로직이 두 종류다"** 이고,
> 여기서 파생된 세 가지 — `@update:model-value` / 오케스트레이션 / fetch 금지 — 를 같이 정리한다.

---

# 1. 로직은 두 종류다

| | 이름 | 예 | 어디 있나 |
|---|---|---|---|
| ① | **업무 로직** (비즈니스·도메인 로직) | 합계 = 수량 × 단가<br>규격 벗어나면 FAIL<br>NONE이 하나라도 있으면 종합판정 NONE | **분리 대상** |
| ② | **화면 로직** (UI·프레젠테이션 로직) | 화면 뜨면 조회<br>콤보 바꾸면 재조회<br>로딩 표시 / 에러 배너 | ⭐ **화면에 남는다** |

> **"화면과 로직 분리" = "화면에서 ①만 빼낸다"**
> **②는 남아야 정상이다.** 없으면 화면이 안 돈다.

## 🔑 구분하는 결정적 테스트

> ### **"화면 없이 배치(batch)로 돌린다면 이 코드가 필요한가?"**

| 코드 | 배치로 돌릴 때 | 판정 |
|---|---|---|
| `amount = qty * unitPrice` | ✅ 필요 | **업무 로직** → 뺀다 |
| `totalAmount = reduce(...)` | ✅ 필요 | **업무 로직** → 뺀다 |
| `custTable.find(...)` 조인 | ✅ 필요 | **업무 로직** → 뺀다 |
| `onMounted(() => load())` | ❌ 불필요 | **화면 로직** → 남긴다 |
| `@update:model-value="load"` | ❌ 불필요 | **화면 로직** → 남긴다 |
| `loading.value = true` | ❌ 불필요 | **화면 로직** → 남긴다 |

**이 질문 하나로 전부 갈린다.**

## 🍜 식당으로 보면

```
주방    : 요리한다                          ← 업무 로직
홀 직원 : 손님이 앉으면 주문서를 주방에 넣는다  ← ⭐ 화면 로직
```

**주문서를 넣는 것도 "일"이다. 하지만 요리는 아니다.**

😖 홀 직원이 없으면 — **주방은 멀쩡한데 아무도 주문을 안 넣는다.** 음식이 안 나온다.
그래서 화면에 `onMounted(load)` 가 있는 건 **정상이다.**

## 분리 후 화면에 남는 것 (전부)

```js
const selected = ref(null)     // 화면 상태 — 지금 뭘 골랐나
const sheet    = ref(null)     // 받아온 것을 담을 그릇
const loading  = ref(false)    // 로딩 표시

function load() {
  sheet.value = fetchOrder(selected.value)   // 주방에 주문서 넣고 받아옴
}

onMounted(load)                // 언제 부를지 — 화면의 사정
```

> **"언제 부를지"는 화면이 정하고, "무엇을 계산할지"는 업무가 정한다.**

# 2. `@update:model-value` 는 원래 HTML의 뭔가

## 원래 HTML은 이랬다

```html
<select onchange="load()">
  <option value="A">가</option>
</select>
```

## Vue + Quasar 에서는

```html
<q-select v-model="selected" @update:model-value="load" />
```

## 🟢 왜 다른가 — **q-select 는 진짜 `<select>` 가 아니다**

브라우저에서 개발자도구로 열어보면 `<select>` 태그가 **아예 없다.** 이렇게 생겼다:

```html
<div class="q-field">          ← 그냥 div
  <input readonly>              ← 표시용. 진짜 입력칸이 아님
</div>
<div class="q-menu">            ← 드롭다운은 완전히 다른 위치에 뜬다
  <div class="q-item">가</div>  ← option 이 아니라 div
</div>
```

**`<select>` 가 없으니 `onchange` 도 없다.** 붙일 곳이 없는 것이다.

그래서 Quasar 가 자기만의 신호를 만들었다 → **`update:model-value`**

### 😖 기존 HTML 이벤트를 쓰면 겪는 고통

```html
<q-select @change="load" />     ← 🚨 아무 일도 안 일어난다
```

**에러도 안 난다. 콘솔도 조용하다. 그냥 안 된다.**

🟢 **한국 콘센트에 유럽 플러그를 꽂는 것.** 부러지지도 않고 불꽃도 안 튄다. **그냥 안 들어간다.**

📌 이게 오늘 배운 **"조용한 실패"** 의 한 종류다. MES에서 겪은 4종 중 첫 번째(없는 슬롯에 값을 넘김)와 같은 원리.

## 그럼 왜 진짜 `<select>` 를 안 쓰나

| | `<select>` (기성복) | `q-select` (맞춤복) |
|---|---|---|
| 만들기 | 😀 한 줄 | 😖 라이브러리 필요 |
| 색·모양 바꾸기 | 🚨 **거의 불가** (브라우저가 그림) | 😀 자유 |
| 옵션에 아이콘·2줄 | 🚨 불가 | 😀 가능 |
| 검색해서 고르기 | 🚨 불가 | 😀 가능 |
| 이벤트 | `onchange` | **`update:model-value`** |

🟢 **기성복은 빨리 입지만 수선이 안 된다.** 맞춤복은 원하는 대로 되지만 **단추 다는 법이 다르다.**

## `v-model` 과의 관계 — 사실 한 세트다

```html
<q-select v-model="selected" />
```

이건 **축약형**이다. 풀어 쓰면:

```html
<q-select
  :model-value="selected"                      ← 값을 내려준다
  @update:model-value="selected = $event"      ← 값이 바뀌면 받는다
/>
```

**내려주기 + 받기가 한 묶음**이다. 그래서 이름이 `v-model` (model 을 양방향으로).

그럼 `@update:model-value="load"` 를 **따로 또 붙이는 건** 무슨 뜻인가?

> **"값을 받는 김에 `load` 도 불러라"**

`v-model` 이 값을 먼저 반영하고, 그 다음 `load` 가 불린다. 그래서 `load` 안에서 `selected.value` 를 읽으면 **이미 새 값이 들어 있다.**

📌 실무 요약: **`onchange` 자리에 `@update:model-value` 를 쓴다.** 그게 전부다.

# 3. 오케스트레이션이란

## 🟢 오케스트라 지휘자

**지휘자는 악기를 하나도 안 분다.**
바이올린도 안 켜고 트럼펫도 안 분다. 하는 일은 딱 하나 —

> **"언제 누가 연주할지"** 를 정한다.

각 연주자는 자기 악기를 어떻게 다루는지 **이미 안다.** 지휘자가 가르치지 않는다.

## 코드로 보면

```js
onMounted(load)                    // 막이 오르면 → 연주 시작
@update:model-value="load"         // 곡이 바뀌면 → 다시 연주
@click="save"                      // 저장 누르면 → 저장 연주
```

**`load` 안에서 뭘 계산하는지 화면은 모른다.** 그냥 *"지금 불러라"* 만 안다.

## 🍜 더 쉬운 예 — 라면 끓이기

```
① 물을 올린다
② 끓으면 면을 넣는다
③ 3분 뒤 스프를 넣는다
```

**이게 오케스트레이션이다.** 물이 어떻게 끓는지, 면이 어떻게 익는지는 **안 만든다. 순서만 정한다.**

## 😖 없으면 / 잘못되면

| 상황 | 결과 |
|---|---|
| 오케스트레이션이 **없다** | 화면은 떴는데 데이터가 안 나온다. **아무도 부르지 않아서** |
| 순서가 **틀렸다** | 스프 먼저 넣고 면 넣기 → 짜다. 코드로는 *"저장 메시지 띄우고 → 조회하니 메시지가 지워짐"* |
| 지휘자가 **직접 연주한다** | 화면 안에 계산이 섞임 → 지휘가 안 됨 |

> 📌 **MES에서 실제로 겪은 사고**: `save()` 가 성공 메시지를 세팅한 뒤 `load()` 를 불렀는데,
> `load()` 안에서 `clearMessages()` 를 실행해서 **메시지가 즉시 지워졌다.**
> 계산은 다 맞았다. **순서만 틀렸다.** 이게 오케스트레이션 버그다.

## 어디에 있나

| 위치 | 예 |
|---|---|
| `.vue` 의 `<script setup>` | `onMounted`, `watch`, 이벤트 핸들러 |
| `composables/` | 여러 화면이 같은 순서를 쓸 때 빼둔다 |

# 4. "컴포넌트는 데이터를 직접 fetch 하지 않는다"

## 🟢 직접 창고에 가지 말고, 주문서를 넣어라

```js
// ❌ 화면이 직접 창고까지 트럭 몰고 감
const res = await fetch('http://api.company.com/v2/orders?no=001', {
  headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' }
})
if (res.status === 401) { /* 로그인 만료 처리 */ }
if (res.status === 500) { /* 서버 에러 처리 */ }
const data = await res.json()

// ✅ 주문서만 넣는다
const data = await fetchOrder('001')
```

**둘 다 "부른다"는 건 같다.** 차이는 **화면이 뭘 알아야 하느냐**다.

## ❌ 직접 fetch 하면 화면이 알아야 하는 것

| 알아야 할 것 | 바뀌면? |
|---|---|
| 서버 주소 | 주소 바뀌면 **모든 화면 수정** |
| 인증 토큰 붙이는 법 | 방식 바뀌면 **모든 화면 수정** |
| HTTP 상태코드 처리 (401, 403, 500) | 규칙 바뀌면 **모든 화면 수정** |
| JSON 파싱 · 에러 형태 | " |
| 타임아웃 · 재시도 | " |

**화면이 10개면 이게 10곳에 복사돼 있다.**

### 😖 실제로 벌어지는 일

```
서버 주소가 api.company.com → api2.company.com 으로 바뀜
        ↓
10개 화면을 다 고쳐야 함
        ↓
🚨 1개를 빠뜨림
        ↓
그 화면만 안 됨. 그런데 아무도 모름 (자주 안 쓰는 화면이라)
        ↓
한 달 뒤 현업이 발견. "이 화면 원래 안 됐어요?"
```

## ✅ 전용 레이어를 거치면

```
화면 10개  →  api/orders.js  →  api/http.js  →  서버
                (주문서)         (트럭 한 대)
```

**주소·토큰·에러 처리는 `http.js` 한 곳에만 있다.** 주소가 바뀌면 **한 줄 고친다.**

🟢 **택배.**
- ❌ 물건 필요할 때마다 **내가 직접 창고까지 트럭 몰고 간다**
- ✅ **주문서를 넣으면** 택배기사가 알아서 갖다 준다

**창고 위치가 바뀌어도 나는 모른다. 주문서 양식은 그대로다.**

## ⭐ 준이 물은 것 — "부르지도 말라는 게 아니다"

**맞다. 주문서는 넣어야 한다.** 안 넣으면 아무것도 안 온다.

> **금지된 건 "트럭을 직접 모는 것"이지 "주문하는 것"이 아니다.**

| | 화면이 해도 되나 |
|---|---|
| `fetchOrder(...)` 를 **부른다** | ✅ **당연히 한다** |
| 언제 부를지 정한다 (`onMounted`) | ✅ 화면의 일 |
| 받아온 걸 화면 변수에 담는다 | ✅ 화면의 일 |
| `fetch()` / `axios` 를 **직접 쓴다** | ❌ 전용 레이어로 |
| 서버 주소 문자열을 안다 | ❌ |
| 토큰을 붙인다 | ❌ |

## MES에서 실제 구조

```
CoaPrintPage.vue          await fetchCoaPrintData(lotNo)   ← 주문서만 넣음
      ↓
api/quality.js            post(QUALITY_API.COA_PRINT_DATA) ← 주소를 안다 (전화번호부)
      ↓
api/http.js               실제 통신 · 에러 · 토큰          ← 트럭
```

> 📌 그래서 **자바 백엔드로 바꿀 때 `http.js` 하나만 바뀐다.** 화면 5개는 한 줄도 안 건드린다.
> 이게 이 구조의 값어치다. 대신 **역추적 왕복이 2회 늘어난다** — 오늘 MES에서 8왕복 한 이유.

# 5. 한 장 요약

```
┌─────────────────────────────────────────────┐
│  화면 (.vue)                                 │
│   · 화면 상태 (ref)                          │
│   · 언제 부를지 (onMounted, 이벤트) ← 오케스트레이션 │
│   · 받아온 걸 담기                            │
│   · @update:model-value  ← onchange 자리      │
└──────────────────┬──────────────────────────┘
                   │ 주문서만 넣는다
┌──────────────────▼──────────────────────────┐
│  업무 로직 (api/, services/, utils/)          │
│   · 계산 · 조인 · 판정                        │
│   · 화면이 없어도 필요한 것                    │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  통신 (http.js) — 주소·토큰·에러 한 곳에만     │
└─────────────────────────────────────────────┘
```

## 판단이 헷갈리면 이 질문 하나

> ### **"화면 없이 배치로 돌린다면 이 코드가 필요한가?"**
>
> **필요하다 → 빼낸다. 불필요하다 → 화면에 남긴다.**
