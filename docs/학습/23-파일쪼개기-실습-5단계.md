# 파일 쪼개기 로드맵 — 한 덩어리에서 4층까지

> **목적**: 파일을 왜 쪼개는지 **설명으로 배우지 않고, 아파보고 배운다.**
> 거래명세서 하나를 **전부 한 파일**로 만들어 놓고, 현업 요청을 받으며 **아픈 지점이 생길 때만** 쪼갠다.
> 매 단계 **지표 5개**를 실측해서 "무엇이 좋아지고 무엇이 나빠졌는지"를 숫자로 남긴다.

---

## 0. 왜 이 실습을 하는가

2026-09-06 실습에서 준이 스스로 발견한 것:

> *"MES는 어려웠고 거래명세서는 쉬웠다. 이것도 파일 쪼개는 원리 같은데."*

| | MES 성적서 | 거래명세서 |
|---|---|---|
| 파일 | 11개 | 3개 |
| 층 | 4단계 | 2단계 |
| 첫 역추적 | **8왕복** | **4왕복** |

**같은 일을 하는데 난이도가 2배.** 그 차이가 어디서 오는지를 **직접 만들어보며** 확인한다.

---

## 1. 측정 지표 5개

매 단계 끝나면 이 표를 채운다. **채워진 표가 이 실습의 최종 산출물이다.**

| 지표 | 재는 법 |
|---|---|
| **① 파일 수** | 세면 됨 |
| **② 역추적 왕복** ⭐ | 화면의 `합계금액` → 원본 데이터까지 **파일을 몇 번 옮기나** |
| **③ 계산만 테스트** | 화면 없이 합계 계산을 검사할 수 있나 (○/×) |
| **④ 두 화면 재사용** | 같은 명세서 표를 인쇄화면에서도 쓸 수 있나 (○/×) |
| **⑤ 백엔드 교체 범위** | 자바로 바꿀 때 **몇 개 파일**이 바뀌나 |

> ②가 오를수록 **읽기가 어려워진다.** ③④⑤가 좋아질수록 **고치기가 쉬워진다.**
> **둘은 반대 방향이다.** 이게 이 실습의 결론이 될 것이다.

---

## 2. 로드맵

```
Step 0  전부 한 파일            [ 1개 ]
   ↓  🩹 요청 4개를 받아본다 — 어디가 아픈가
Step 1  데이터 분리             [ 2개 ]
   ↓  🩹 테스트를 못 한다
Step 2  계산 분리               [ 3개 ]
   ↓  🩹 인쇄 화면에 복붙이 생긴다
Step 3  화면 조각 분리          [ 4개 ]
   ↓  🩹 자바로 바꾸면 다 뒤집어야 한다
Step 4  통신 층 분리 (MES 구조) [ 6개 ]
```

## 3. 단계별 계획

### Step 0 — 종합 선물세트 (전부 한 파일)

| | |
|---|---|
| **파일** | `split/step0/OrderAllInOne.vue` |
| **안에 든 것** | 화면 + 계산 + 데이터 + 스타일 **전부** |
| **작동** | ✅ 정상. 아무 문제 없다 |

> 📌 **이게 나쁜 코드가 아니다.** 화면 하나, 혼자 만들고, 안 바뀔 거면 **이게 정답이다.**

#### 🩹 여기서 받아볼 요청 4개

| # | 요청 | 무엇을 확인하나 |
|---|---|---|
| R1 | *"부가세 10% 도 보여주세요"* | 계산 코드가 어디 있는지 찾을 수 있나 |
| R2 | *"금액을 빨간색으로"* | 스타일이 계산 사이에 섞여 있나 |
| R3 | *"인쇄 화면에도 같은 표를"* | 🚨 **복사-붙여넣기가 생기나** |
| R4 | *"합계가 맞는지 테스트하고 싶다"* | 🚨 **화면 없이 계산만 검사되나** |

**R3·R4에서 아플 것이다.** 그게 다음 단계의 이유가 된다.

---

### Step 1 — 데이터 분리

| | |
|---|---|
| **왜** | 데이터가 코드 사이에 섞여 있어 **어디까지가 데이터인지** 안 보임 |
| **결과** | `orderSeed.js` + `OrderPage.vue` |
| **좋아지는 것** | 데이터만 고칠 때 화면 코드를 안 건드림 |
| **나빠지는 것** | 역추적 왕복 +1 |

---

### Step 2 — 계산 분리

| | |
|---|---|
| **왜** | **R4** — 합계 계산만 따로 테스트하고 싶다 |
| **결과** | `ordersApi.js` 추가 |
| **좋아지는 것** | 테스트 가능 ○ / 계산 규칙이 한곳에 모임 |
| **나빠지는 것** | 역추적 왕복 +1 |

> 🟢 **국물 간만 보려는데 그릇째 들어야 하는 것.** 계산이 화면에 붙어 있으면 화면을 띄워야 검사가 된다.

---

### Step 3 — 화면 조각 분리

| | |
|---|---|
| **왜** | **R3** — 인쇄 화면에도 같은 표가 필요하다 |
| **결과** | `OrderSheet.vue` (명세서 종이 부분만) 추가 |
| **좋아지는 것** | 두 화면이 같은 표를 씀. 한 곳만 고치면 둘 다 바뀜 |
| **나빠지는 것** | 역추적 왕복 +1, **`defineProps` 등장** → 부모 찾기가 필요해짐 |

> ⚠️ 오늘 MES에서 **8왕복 중 3왕복이 여기서 생겼다.** `defineProps` 를 만나면 파일 밖으로 나가야 한다.

---

### Step 4 — 통신 층 분리 (MES 구조 완성)

| | |
|---|---|
| **왜** | 나중에 자바 백엔드로 교체. 화면을 안 건드리고 갈아끼우고 싶다 |
| **결과** | `api/orders.js`(전화번호부) + `api/http.js`(가짜 서버) |
| **좋아지는 것** | ⭐ **자바 붙일 때 `http.js` 하나만 바뀜** |
| **나빠지는 것** | 역추적 왕복 +2 (전화번호부에서 한 번, 서버에서 한 번) |

> 📌 **이게 MES 구조다.** 여기까지 오면 준이 오늘 8왕복 한 이유가 전부 설명된다.

### 지금까지 읽히는 것

```
②역추적왕복   0 → 1 → 2      ▲ 계속 나빠진다 (읽기가 어려워진다)
```

## 5. 진행 규칙

- 한 단계씩. **각 단계마다 브라우저에서 화면이 똑같이 보이는지 확인**한다 (겉은 같고 속만 다르다).
- 준이 **먼저 예상**하고 시작한다: *"이걸 쪼개면 뭐가 좋아질까 / 나빠질까"*
- 앨리는 **답을 먼저 말하지 않는다.** 막히면 다음 한 걸음만.
- 각 단계 끝에 **② 역추적 왕복을 직접 세어본다.**
