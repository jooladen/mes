# 코드로 역추적하기 — 물어볼 사람이 없을 때

> `10-결과물부터-거꾸로-일하는법.md` 는 **사람에게 묻는 법**이었다. 이 문서는 **코드에서 스스로 찾는 법**이다.
>
> 둘은 경쟁이 아니라 **짝**이다. 순서가 있다.

---

## 0. 왜 둘 다 필요한가

```
❌ 아무것도 모르는 채 현업에게 간다   →  질문이 많고 막연하다. 상대가 지친다
✅ 코드로 먼저 30분 훑는다  →  ❓ 가 줄어든다  →  남은 것만 묻는다
```

🟢 **병원 가기 전에 증상을 메모해가는 것**과 같다.
*"어디가 아파요?"* 에 *"몰라요 그냥 아파요"* 보다, *"3일 전부터 아침에만 여기가 아파요"* 가 훨씬 빨리 진단된다.

### 알려주는 게 서로 다르다

| | 💻 코드/쿼리 | 🧑 사람(현업) |
|---|---|---|
| **아는 것** | **무엇을** 하는가 (정확) | **왜** 그렇게 하는가 |
| | 어느 테이블에서 오는가 | 어떤 예외가 있는가 |
| | 지금 실제로 어떻게 도는가 | 앞으로 어떻게 바뀔지 |
| **거짓말** | **안 한다** | 기억이 틀릴 수 있다 |
| **한계** | *"왜 이렇게 정했는지"* 모른다 | *"진짜 그렇게 도는지"* 모른다 |

😖 **코드만 보면**: `LATEST_YN='Y'` 필터를 발견하지만 **왜 있는지** 모른다 → 잘못 건드린다.
😖 **사람만 물으면**: *"재검사하면 최신 걸로 봐요"* 는 듣지만 **어디에 그 로직이 있는지** 모른다 → 못 고친다.

## 1. 5단계 역추적법

### 🎯 목표: 화면의 값 하나 → 그 값이 저장된 테이블·컬럼

```
① 화면 글자로 파일 찾기
        ↓
② 그 파일에서 변수 이름 얻기
        ↓
③ 변수 이름으로 전체 검색
        ↓
④ 서버(API) 쪽 코드 찾기
        ↓
⑤ 테이블·컬럼 확인
```

---

### ① 화면에 보이는 글자로 파일을 찾는다

화면에서 **고유해 보이는 한글**을 하나 고른다. 흔한 단어(`저장`, `조회`)는 피한다.

```bash
grep -rl "출 하 성 적 서" src/
# → src/components/CoaSheet.vue
```

🟢 **책에서 기억나는 문장으로 페이지 찾기.** 페이지 번호를 몰라도 문장 하나면 찾는다.

> 💡 **한글이 안 잡히면**: 화면을 우클릭 → 검사(Inspect) → 그 요소의 `class` 이름으로 검색한다.

---

### ② 그 파일에서 값을 그리는 줄을 찾는다

```bash
grep -n "측정값" src/components/CoaSheet.vue
# → 67: <th class="w-val">측정값</th>       ← 열 제목

grep -n "formatMeasured\|measuredVal" src/components/CoaSheet.vue
# → 79: {{ formatMeasured(d.measuredVal, d.decimalLen) }}
```

**여기서 변수 이름을 얻는다: `measuredVal`**

> 💡 이게 **가장 중요한 한 걸음**이다. 한글 "측정값"은 화면에만 있지만, `measuredVal` 은 **서버·DB까지 이어지는 이름**이다.

🟢 **별명을 알아낸 것**과 같다. *"그 키 큰 애"* 로는 못 찾지만 **학번**을 알면 어디서든 찾는다.

---

### ③ 변수 이름으로 전체를 훑는다

```bash
grep -rn "measuredVal" src/ --include="*.js" --include="*.vue" | grep -v test
```

결과가 쭉 나온다. **`api/` 폴더에 있는 것**이 서버 쪽이다.

```
api/http.js:171     measuredVal: r.measuredVal,      ← 성적서 만들 때
api/http.js:435     measuredVal: Number(row.measuredVal),  ← 저장할 때
pages/InspectionPopPage.vue:112  ...                 ← 화면에서 입력할 때
```

> 💡 **읽는 순서**: 화면(`pages/`) → 창구(`api/quality.js`) → 서버(`api/http.js`)
> 진짜 회사 코드라면 → 컨트롤러 → 서비스 → 매퍼 XML → SQL

---

### ④ 서버 코드에서 "어디서 가져오나"를 본다

```bash
sed -n '155,175p' src/api/http.js
```

```js
const results = latestResults(lot.lotNo)   // ← 이 함수가 원천이다
...
measuredVal: r.measuredVal,
```

**모르는 함수가 나오면 그것도 찾는다:**

```bash
grep -n -B4 -A3 "const latestResults" src/api/http.js
```

```js
/** 그 Lot 의 최신 실적만 (`LATEST_YN='Y'`) — F2 design §4 */
const latestResults = (lotNo) =>
  inspTable.filter((r) => r.lotNo === lotNo && r.latestYn === 'Y')
```

**여기서 두 가지를 동시에 얻었다:**
1. 원천 = `inspTable` (= `TRN_INSP_RESULT`)
2. **숨은 조건 = `latestYn === 'Y'`** ← 이건 화면만 봐선 절대 모른다

---

### ⑤ 테이블·컬럼을 확인한다

```bash
grep -rn "MEASURED_VAL" docs/02-design/mes-coa-s1.data-model.md
```

```
| `MEASURED_VAL` | `NUM(18,6)` | | N | **측정값** |
```

**완료. 전체 경로:**

```
화면 "측정값 470.0"
  ↓ CoaSheet.vue:79
measuredVal
  ↓ api/http.js:171 buildCoaDetail()
latestResults(lotNo)
  ↓ latestYn === 'Y' 필터
TRN_INSP_RESULT.MEASURED_VAL
```

## 2. 진짜 회사 코드에서 쓰는 기술

위 예시는 **주석이 친절한** 코드였다. 실제 회사 코드는 대체로 이렇지 않다.

### 🔍 기술 ① 개발자도구 Network 탭 — **가장 확실하다**

`F12` → **Network** → 화면에서 버튼 클릭 → 새로 뜨는 요청을 본다.

| 볼 것 | 알 수 있는 것 |
|---|---|
| **요청 URL** | 서버 어느 엔드포인트인지 → 컨트롤러를 바로 찾는다 |
| **Payload** | 화면이 서버에 **뭘 보내는지** |
| **Response** | 서버가 **뭘 돌려주는지**. **키 이름이 곧 컬럼 이름**인 경우가 많다 |

🟢 **편지 봉투의 주소를 보는 것.** 편지 내용을 몰라도 어디서 왔는지는 안다.

> ⚠️ **이 프로젝트는 Mock이라 Network에 안 잡힌다.** 자바가 붙으면 그때부터 보인다.

### 🔍 기술 ② 화면의 특이한 값으로 DB 검색

화면에 보이는 **드문 값**을 그대로 DB에서 찾는다.

```sql
-- 성적서번호처럼 유일한 값이 최고다
SELECT * FROM TRN_COA WHERE COA_NO = 'CoA-20260905-001';

-- 어느 테이블인지도 모르겠으면, 의심 가는 테이블을 하나씩
SELECT * FROM TRN_INSP_RESULT WHERE MEASURED_VAL = 470.0;
```

🟢 **물건에 적힌 일련번호로 창고에서 찾기.** 어느 선반인지 몰라도 번호로 찾는다.

> 💡 **주의**: `1`, `Y`, `0` 같은 흔한 값으로 찾으면 안 된다. **날짜+번호 조합**처럼 드문 값을 고른다.

### 🔍 기술 ③ SQL 로그 켜기

MyBatis 는 설정 한 줄로 **실행되는 SQL을 전부 콘솔에 찍는다.**

```properties
# application.properties
logging.level.com.회사.mapper=DEBUG
```

화면에서 버튼 하나 누르고 로그를 보면 **그 화면이 때리는 쿼리 전부**가 나온다.

🟢 **가게에 CCTV를 다는 것.** 누가 뭘 가져갔는지 다 찍힌다.

> 😀 **이게 가장 빠른 방법일 때가 많다.** 코드를 10분 읽는 것보다 로그 한 줄이 정확하다.

### 🔍 기술 ④ 컬럼명이 이상할 때 — 값으로 추론

실제 회사 테이블엔 이런 컬럼이 흔하다: `COL1`, `FLAG2`, `ETC_VAL`, `USE_YN3`

이럴 땐 **데이터를 직접 본다.**

```sql
SELECT COL1, COUNT(*) FROM 테이블 GROUP BY COL1;
```

- 값이 `Y`/`N` 두 개뿐 → **플래그**다
- 값이 날짜 형태 → **일시**다
- 값이 100가지 넘고 다 다름 → **키 or 사용자 입력값**이다

🟢 **모르는 서랍을 열어보는 것.** 라벨이 없으면 안에 든 걸 보고 짐작한다.

## 3. 코드가 절대 안 알려주는 것

여기가 **사람에게 물어야 하는 영역**이다.

| 코드가 말해주는 것 | 코드가 **안** 말해주는 것 |
|---|---|
| `LATEST_YN='Y'` 로 거른다 | **왜** 이전 값을 지우지 않는가 |
| `shipQty <= goodQty` 를 검사한다 | 초과하면 **누가 곤란해지는가** |
| `LOT_STATUS='OK'` 만 목록에 올린다 | 예외적으로 발행해야 하는 경우가 **있는가** |
| 규격을 `MST_INSP_SPEC` 에서 읽는다 | 규격이 바뀌면 **누구에게 알려야 하는가** |
| — | 이 값이 틀리면 **회사가 얼마를 손해보는가** |
| — | 지금 **불편한 점**은 무엇인가 |

😖 **코드만 보고 고치면 생기는 일**
> `LATEST_YN` 필터가 왜 있는지 몰라서 지운다 → 재검사 이력이 성적서에 다 찍힌다 → 고객사가 *"왜 불합격 기록이 있냐"* 고 묻는다 → 사고.

> 🟢 **남의 집 두꺼비집을 만지는 것**과 같다. 스위치가 뭘 하는지는 보이지만, **왜 그게 항상 켜져 있는지**는 물어봐야 안다.

## 4. 실전 순서 — 30분 + 30분

### 🕐 첫 30분 — 혼자 코드로

1. 출력물의 칸에 번호를 매긴다 (`11-현업에게-물어볼-질문표.md`)
2. **눈에 띄는 칸 3~5개만** 코드로 역추적한다 (전부 할 필요 없다)
3. 알아낸 건 표에 채우고, **못 알아낸 것과 "왜?"가 궁금한 것은 ❓ 로 남긴다**

### 🕑 다음 30분 — 사람에게

4. **줄어든 ❓ 만** 들고 간다
5. 코드로 알아낸 건 **확인만** 받는다
   > *"⑬번 측정값은 검사 화면에서 넣고, 재검사하면 최신 것만 본다고 코드에 있던데 맞나요?"*
6. **여기서 신뢰가 생긴다** — *"이 사람 미리 보고 왔구나"*

😀 **이 한 문장이 첫 주의 인상을 결정한다.**
> ❌ *"MES가 뭔가요?"*
> ✅ *"코드 보니 이렇게 도는 것 같은데, 맞나요?"*

## 5. 이 프로젝트로 연습하기

지금 바로 해볼 수 있는 것들이다. 답은 아래에 있다.

| 연습 | 힌트 |
|---|---|
| ⑫ **규격** `400 ~ 500` 은 어디서? | `formatSpecRange` 부터 시작 |
| ⑭ **판정** `PASS` 는 누가 정하나? | `judgeResult` 로 검색 |
| ① **성적서번호** 는 어떻게 만들어지나? | `coaNo` 로 검색 |
| ⑨ **No.** 는 왜 항상 1부터인가? | `printSeq` 로 검색 |

<details>
<summary>답 보기</summary>

- **⑫ 규격**: `MST_INSP_SPEC.LSL` / `USL` → F1 화면에서 품질담당자가 등록.
  화면 표기는 `utils/specFormat.js` 의 `formatSpecRange()` 가 조립 (DB에 문자열로 저장하지 않는다)
- **⑭ 판정**: `utils/specJudgeClient.js` 의 `judge()`.
  **화면과 서버가 각각 계산**하고 **서버 값이 최종** (F2 design §2)
- **① 성적서번호**: `api/http.js` 의 `nextCoaNo()`. `CoA-날짜-그날순번`, 3자리 zero-fill
- **⑨ No.**: `buildCoaDetail()` 의 `printSeq`. `sortNo`(1,2,5,9처럼 빌 수 있음)를
  **인쇄 시점에 1부터 다시** 매긴다 (F3 design §3.0 D3)

</details>

## 6. 요약

```
💻 코드  =  무엇을 (What)   — 정확하다. 거짓말 안 한다
🧑 사람  =  왜   (Why)     — 코드에 없다. 물어야만 안다

순서: 코드 먼저 → ❓ 줄이기 → 남은 것만 묻기
```

> 🟢 **지도를 보고 간 뒤 길을 묻는 것**과 같다.
> 지도 없이 물으면 *"어디 가시는데요?"* 부터 시작하지만,
> 지도를 보고 *"여기서 왼쪽 맞나요?"* 라고 물으면 **10초 만에 답이 온다.**
