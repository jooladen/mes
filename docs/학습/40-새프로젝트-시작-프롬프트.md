# 재사용 프롬프트 — 오늘 한 것을 다음 프로젝트에서 그대로

> **오늘 한 것**: 설계 → 구현 → 브라우저 실측 → 테스트 → 문서 5종 → 실습 시나리오 → 역추적 연습
> 이걸 **다음 프로젝트에서도 똑같이** 하려면 뭐라고 시켜야 하는지, 그 문장을 만들어 둔다.

---

## 0. 🟢 프롬프트가 뭔가 — 레시피다

| | |
|---|---|
| ❌ *"맛있게 해줘"* | 레시피가 아니다 |
| ✅ *"소금 1작은술, 180도에서 20분"* | **레시피다** |

😖 *"MES 만들어줘"* 라고 하면 AI가 **자기 맘대로** 만든다. 그리고 원하던 게 아닌 게 나온다.

🟢 **택시 기사에게** *"빨리 가주세요"* 하면 기사 마음대로 간다.
*"강남역 2번 출구요. 사거리에서 좌회전 말고 직진해주세요"* 라고 해야 원하는 길로 간다.

> **프롬프트를 상세히 쓰는 건 잔소리가 아니라 목적지를 정확히 말하는 것이다.**

# 1부 — 🔴 복사해서 쓰는 프롬프트 (전문)

> 새 프로젝트 시작할 때 **이걸 통째로** 붙여넣는다.
> `[대괄호]` 부분만 자기 프로젝트에 맞게 바꾼다.

```text
[프로젝트명]을 만들려고 한다. 아래 방식으로 진행해줘.

═══════════════════════════════════
【0】 시작 전 — Output 먼저 못박기
═══════════════════════════════════
- 이 프로그램의 최종 산출물(terminal output)이 뭔지 한 문장으로 먼저 확정할 것.
  예: "고객사에 나가는 출하성적서 종이 한 장"
- 그 산출물의 칸을 전부 나열하고, 각 칸의 값이 어디서 오는지 역산할 것.
- 역산 결과가 곧 화면 목록·테이블 목록이다. 이걸 먼저 보여주고 내 확인을 받을 것.
- ⚠️ 최종 산출물을 한 문장으로 못 쓰면 착수하지 말고 나에게 되물을 것.

═══════════════════════════════════
【1】 설계 — 문서 먼저, 단 완벽주의 금지
═══════════════════════════════════
- 기능별 설계 문서를 쓰되, 각 API의 요청/응답 키를 표로 명시할 것.
- 설계 판단마다 D번호(D1, D2...)를 붙이고 "왜 그렇게 정했는지"를 인용문으로 남길 것.
  → 나중에 코드에서 (D27) 을 보면 문서에서 검색할 수 있게.
- 에러코드는 한 곳에 모아 레지스트리로 관리할 것.

⚠️ 여기서 시간을 태우지 말 것:
- 설계 문서의 "완성도 점수"를 100점으로 만들려고 반복하지 말 것.
- 코드가 없는 상태에서 "설계↔구현 일치율" 같은 지표를 쫓지 말 것.
  (그건 코드가 생긴 뒤에 재야 의미가 있다)
- 설계 문서는 "구현을 시작할 수 있을 만큼"이면 충분하다. 나머지는 만들면서 고친다.

═══════════════════════════════════
【2】 구현 — 만들면 반드시 눌러본다
═══════════════════════════════════
- 화면 하나를 만들 때마다 즉시:
  ① 빌드 통과 확인
  ② dev 서버를 띄우고 **브라우저에서 직접 클릭해서** 동작 확인
  ③ 정상 경로 + 실패 경로(빈 값 저장, 규격 위반 등)를 둘 다 눌러볼 것
- ⚠️ "빌드 통과 = 정상 동작"이 아니다. 반드시 눈으로 확인할 것.
- 콘솔 에러가 없어도 화면이 틀릴 수 있다. 특히 다음을 조심:
  · 라이브러리에 없는 슬롯/옵션에 값을 넘김 → 조용히 무시됨
  · 라이선스 없는 상용 라이브러리 → 예외로 화면이 통째로 죽음
  · 그리드에 선언 안 한 필드를 넘김 → 말없이 버려짐
  · DB 행을 그대로 응답에 실음 → 계약에 없는 키가 새어나감
- 초기화 코드는 try/catch 로 감싸서 **실패를 화면에 보여줄 것.**
  조용히 죽으면 "데이터가 없나 보다"로 오해한다.

═══════════════════════════════════
【3】 설계서가 틀렸으면 설계서를 고친다
═══════════════════════════════════
- 만들다가 설계서가 틀린 걸 발견하면:
  ① 코드를 맞게 고치고
  ② **설계서도 같이 고치고**
  ③ 왜 틀렸는지를 D번호 붙여 문서에 남길 것
- 고치고 문서를 안 고치면 다음 사람이 같은 함정에 빠진다.

═══════════════════════════════════
【4】 테스트 — 딱 하나는 반드시
═══════════════════════════════════
- 이 프로젝트에서 "여기 한 글자 틀리면 큰일 나는 코드"를 하나 지목할 것.
- 그 코드에 대해서만 단위 테스트를 촘촘히 쓸 것.
  특히 경계값(>= 인지 > 인지), null 과 0 의 구분, 빈 목록.
- 나머지는 나중에.

═══════════════════════════════════
【5】 문서 — 초딩도 알아듣게
═══════════════════════════════════
아래 5종을 만들어줘. 전부 **생활 예제 → 실제 의미 → 파일 위치** 순으로 쓸 것.
"🟢 초딩용 / 🔵 개발자용"을 나눠서 쓰고, 각 개념마다
**"알면 뭐가 좋은지 / 모르면 어떤 고통을 겪는지"** 를 반드시 붙일 것.

① 입문가이드   — 이게 뭐 하는 물건인지 + "이거 고쳐주세요" 요청 시 어느 파일을 여는지
                 (요청을 3단계로 분류: 화면에서 처리 / 안전한 수정 / 위험 구역)
② 용어사전     — 코드·문서에 나오는 용어를 생활 예제로. 약어표 포함
③ 실습 시나리오 — 현업 역할별로 화면을 순서대로 눌러보는 대본.
                 각 단계에 "상황 / 할 일 / 정상이면 이렇게 보임 / 왜 / 일부러 틀려보기"
④ HANDOFF     — 인수인계서. 완성 범위·남은 작업·함정 목록·결정 이력·재개 체크리스트
⑤ 역추적 가이드 — 화면의 값 하나에서 테이블·컬럼까지 찾아가는 5단계

═══════════════════════════════════
【6】 마지막 — 역추적 연습 (⚠️ 코드가 다 생긴 뒤에만)
═══════════════════════════════════
⚠️ 이 단계는 【2】 구현이 끝난 뒤에만 한다. 설계만 있으면 추적할 코드가 없다.

- 최종 산출물의 칸 5개를 골라 "이 값이 어디서 오는지 찾아라"는 연습 문제를 만들어줘.
  쉬운 것 → 어려운 것 순으로 배열할 것.

🔴 실습 규칙 (이게 없으면 연습이 안 된다)
- **답을 먼저 말하지 마.** 나는 VSCode에서 직접 클릭하며 풀 거다.
- 내가 막히면 **다음 한 걸음만** 알려줘. 전체 경로를 보여주지 마.
- 같은 자리에서 **3번 이상 막히면** 그때만 보여줘.
- 내가 "이런 뜻이지?" 하고 해석을 붙이면
  **맞은 부분과 틀린 부분을 구분해서** 답해줘. 뭉뚱그리지 마.
- 각 문제를 끝내면 **왕복 횟수**를 세어줘. 줄어드는 게 보여야 는다.
- 마지막에 **판단 기준**(이런 코드를 만나면 이렇게 해석한다)을 표로 정리해줘.

💡 도구는 grep 말고 **VSCode 단축키**로 안내할 것:
   Ctrl+클릭(앞으로) / Ctrl+Shift+F(뒤로) / Ctrl+F(파일 안)

═══════════════════════════════════
【진행 방식】
═══════════════════════════════════
- 각 단계가 끝나면 멈추고 나에게 결과를 보여줄 것. 한 번에 다 하지 말 것.
- 판단이 필요한 갈림길이 나오면 임의로 정하지 말고 물어볼 것.
  (선택지와 각각의 장단점을 같이 제시)
- 모르면 "모른다"고 할 것. 확인 안 된 걸 확인된 것처럼 말하지 말 것.
- 원인을 못 찾은 문제는 "원인 미상"으로 기록하고 코드를 건드리지 말 것.
```

# 2부 — 왜 이렇게 썼나 (조각별 해설)

## 【0】 Output 먼저 못박기

### 🟢 생활 예제
**김밥을 만들라는데 "어떤 김밥"인지 안 알려준 것.**
참치김밥인지 야채김밥인지 정해야 재료를 산다.

### 😖 이 문장이 없으면
AI가 **"MES니까 이런 게 필요하겠지"** 하고 화면 10개를 만든다.
그중 8개는 안 쓴다. **8개 만든 시간이 통째로 날아간다.**

### 😀 있으면
*"성적서 한 장"* 이 못박히니, **그 종이에 안 찍히는 건 안 만든다.**
칸 16개만 역산하면 필요한 화면·테이블이 저절로 나온다.

---

## 【1】 "완벽주의 금지" — 이 문장이 제일 비싸게 배운 것

### 😖 이 문장이 없어서 실제로 벌어진 일

이 프로젝트에서 **설계 문서 점수(M4)를 100점으로 만들려고 9번을 반복했다. 한 번도 통과 못 했다.**
**4시간이 날아갔다.**

이유는 단순했다. **M4는 "설계서대로 코드를 짰나"를 재는 지표인데, 그때는 코드가 한 줄도 없었다.**

> 🟢 **답안지를 안 낸 상태에서 채점한 것.** 시험지가 문제가 아니라 **재는 시점**이 틀렸다.

코드를 다 만들고 다시 재니 **한 번에 100점**이 나왔고, 그 과정에서 **진짜 버그 3개**를 잡았다.

### 😀 그래서 프롬프트에 넣은 문장

> *"코드가 없는 상태에서 '설계↔구현 일치율' 같은 지표를 쫓지 말 것"*
> *"설계 문서는 구현을 시작할 수 있을 만큼이면 충분하다"*

🟢 **밥 짓기 전에 밥솥을 100번 닦는 것**과 같다. 깨끗한 건 좋지만 **밥이 안 된다.**

---

## 【2】 "만들면 반드시 눌러본다" — 가장 중요한 한 줄

### 😖 이 문장이 없으면 겪는 것

오늘 **빌드도 통과하고 콘솔도 조용한데 화면만 틀린** 경우가 **4번** 있었다.

| # | 무슨 일 | 🟢 비유 |
|---|---|---|
| ① | 없는 슬롯에 값을 넘김 → Vue가 **조용히 무시** | 설계도에 "여기 문에 손잡이 다세요" 인데 **그 자리에 문이 없음** |
| ② | 라이선스 없어 그리드가 **예외로 죽음** | **열쇠가 없으면 문이 안 열리는 게 아니라 문이 무너짐** |
| ③ | 선언 안 한 필드를 넘김 → **말없이 버려짐** | **비행기 수하물에 신고 안 한 물건 넣으면 버려짐** |
| ④ | DB 행을 그대로 응답에 실음 | *"지우개 빌려줘"* 했는데 **필통을 통째로 건네줌** |

**넷 다 에러 메시지가 없었다.** 눌러보지 않았으면 다 넘어갔다.

### 😀 그래서 프롬프트에 넣은 것

> *"빌드 통과 = 정상 동작이 아니다"*
> *"초기화 코드는 try/catch 로 감싸서 실패를 화면에 보여줄 것"*

🟢 **경고등이 안 들어오는 자동차 고장**이 제일 무섭다. 시동도 걸리고 소리도 정상인데 브레이크가 안 듣는다.

---

## 【3】 "설계서가 틀렸으면 설계서를 고친다"

### 😖 없으면
코드만 고치고 문서는 그대로 둔다. **다음 사람이 문서를 믿고 같은 함정에 빠진다.**

실제로 이 프로젝트에서 **설계서가 틀린 게 4번** 있었다:
없는 슬롯 처방 / "라이선스 없으면 평가판" (거짓) / 조회 필터 누락 / 상태 필터로 막힌 경로

### 🟢 생활 예제
**약도를 보고 갔는데 길이 막혀 있어서 돌아갔다.**
나만 돌아가고 약도를 안 고치면, **다음 사람도 똑같이 헤맨다.**

---

## 【4】 "딱 하나는 반드시 테스트"

### 🟢 생활 예제
**요리를 내놓기 전에 소금 맛을 본다.** 전부 다 맛볼 필요는 없다. **간이 결정되는 한 숟갈**만 본다.

### 😖 없으면
이 프로젝트의 판정 코드에서 `<=` 를 `<` 로 한 글자만 틀려도
**규격에 딱 맞는 제품이 전부 불합격**으로 나간다. 그리고 **아무도 모른다.**

### 😀 있으면
"경계값 / null과 0 구분 / 빈 목록" — **이 세 가지만 시켜도** 대부분 잡힌다.

---

## 【5】 "초딩도 알아듣게 + 알면/모르면"

### 😖 없으면
AI가 **개발자용 문서**를 쓴다. *"`LATEST_YN` 플래그를 통해 최신 레코드를 필터링한다"*
→ **맞는 말인데 3개월 뒤의 나도 못 읽는다.**

### 😀 있으면
> 🟢 *"재시험 답안지 여러 장 중 '이게 최종' 스티커"*

**한 번 읽으면 안 잊는다.**

### 💡 "알면 뭐가 좋은지 / 모르면 어떤 고통인지" 를 굳이 시키는 이유

지식은 **"왜 알아야 하는지"** 가 붙어야 남는다.

🟢 **"불조심하세요"** 보다 **"기름 있는 팬에 물 부으면 불기둥이 솟습니다"** 가 100배 기억에 남는다.

---

## 【6】 "역추적 연습 문제"

### 😖 없으면
문서를 읽기만 한다. **읽는 것과 할 줄 아는 것은 다르다.**

오늘 `measuredVal` 하나 찾는 데도 시간이 걸렸다. **그게 정상이다. 연습이 필요하다는 신호다.**

### 🟢 생활 예제
**수영 교본을 다 읽어도 물에 들어가면 가라앉는다.** 발을 담가봐야 한다.

### 😀 있으면
매 프로젝트마다 **연습 문제 5개**가 자동으로 생긴다. 5번 프로젝트면 25번 연습한 셈이다.

---

## 【진행 방식】 — 이게 없으면 제일 괴롭다

| 문장 | 😖 없으면 |
|---|---|
| *"각 단계가 끝나면 멈추고 보여줄 것"* | AI가 **혼자 3시간 달린다.** 결과를 보니 방향이 틀렸는데 **되돌리기엔 너무 많이 왔다** |
| *"갈림길에서 임의로 정하지 말 것"* | AI가 마음대로 정하고, 나중에 *"누가 이렇게 하래?"* 가 된다 |
| *"모르면 모른다고 할 것"* | 확인 안 된 걸 **확신 있게 말한다.** 그걸 믿고 진행하면 사고 |
| *"원인 못 찾으면 코드 건드리지 말 것"* | **멀쩡한 걸 망가뜨린다.** 원인 모르는 수정은 도박이다 |

🟢 **길 안내를 받을 때** — *"쭉 가세요"* 하고 20분 뒤 *"아 아까 거기서 꺾었어야 했는데"* 가 최악이다.
**갈림길마다 확인**받는 게 훨씬 빠르다.

# 3부 — 짧은 버전 (2회차부터)

한 번 해보고 흐름이 익으면 이걸로 충분하다.

```text
[프로젝트명] 만들자. 아래 규칙으로.

1. 최종 산출물(종이/화면 한 장)을 먼저 한 문장으로 확정하고, 그 칸들을 역산해서
   필요한 화면·테이블을 뽑아줘. 내 확인 받고 시작.
2. 설계 문서는 "시작할 수 있을 만큼"만. 완성도 점수 쫓지 마.
3. 화면 하나 만들 때마다 브라우저에서 직접 눌러서 확인. 정상+실패 경로 둘 다.
   빌드 통과 ≠ 정상 동작.
4. 설계서가 틀린 걸 발견하면 코드와 설계서를 같이 고치고 이유를 남겨.
5. "한 글자 틀리면 큰일 나는 코드" 하나만 골라서 경계값 테스트 촘촘히.
6. 문서는 초딩용 생활예제 + "알면 좋은 것 / 모르면 겪는 고통"으로.
   입문가이드 / 용어사전 / 실습시나리오 / HANDOFF / 역추적가이드 5종.
7. 코드가 다 생긴 뒤, "이 값 어디서 오나" 역추적 연습문제 5개.
   ⚠️ 답 먼저 말하지 마. 내가 VSCode로 직접 푼다. 막히면 다음 한 걸음만.
   내가 해석을 붙이면 맞은 것/틀린 것을 구분해서 답해줘. 왕복 횟수를 세어줘.

단계마다 멈추고 보여줘. 갈림길은 물어봐. 모르면 모른다고 해.
```

# 4부 — ⚠️ 한 번에 다 던지지 마라

위 프롬프트를 **통째로 던지면** AI가 3시간 혼자 달린다.

### 🟢 생활 예제
**이사할 때 "다 옮겨주세요"** 하고 나가버리면, 돌아왔을 때 **가구가 엉뚱한 데 놓여 있다.**
방 하나씩 *"여기 침대 놓을게요"* 확인받는 게 낫다.

### 실제로는 이렇게 끊어서 쓴다

| 회차 | 던지는 것 | 받는 것 |
|---|---|---|
| 1 | 【0】만 | 산출물 정의 + 역산된 화면·테이블 목록 |
| 2 | 【1】 | 설계 문서 |
| 3 | 【2】+ "F0부터" | 화면 하나 + 브라우저 검증 결과 |
| 4~ | "다음 화면" | 화면 하나씩 반복 |
| N | 【4】 | 테스트 |
| N+1 | 【5】 | 문서 5종 |
| N+2 | 【6】 | 역추적 연습 문제 |

> 💡 **각 회차 끝에 반드시 눈으로 확인한다.** 화면이면 브라우저에서 직접 눌러본다.

# 5부 — 오늘 겪은 함정 → 프롬프트 어디에 반영됐나

| 오늘 겪은 것 | 잃은 시간 | 반영된 곳 |
|---|---|---|
| 설계 점수 9번 재고 다 실패 | **약 4시간** | 【1】 완벽주의 금지 |
| 없는 슬롯 처방 → 드롭다운 안 열림 | 30분 | 【2】 조용한 실패 4종 |
| 라이선스 없어 화면 죽음 (배너도 없이) | 30분 | 【2】 try/catch + 실패 표시 |
| 그리드 필드 미선언 → 색칠 안 됨 | 20분 | 【2】 조용한 실패 4종 |
| DB 행 그대로 응답 → 키 새어나감 | 20분 | 【2】 + 【3】 |
| 문서만 고치고 코드 안 맞춤 (D39·D41) | 40분 | 【3】 설계서도 같이 |

> **합계 6시간 이상.** 이 프롬프트 한 장이면 다음엔 **대부분 안 겪는다.**

## 6부 — 이 프롬프트의 뼈대 한 줄 요약

```
Output 먼저 못박고  →  설계는 적당히  →  만들면 반드시 눌러보고
   →  틀리면 문서도 고치고  →  위험한 코드 하나만 테스트
   →  초딩도 읽을 문서  →  직접 찾아보는 연습
```

> 뭘 만들지 정하고 → 레시피는 대충 → **간을 보면서** 만들고 → 레시피 틀리면 고쳐 적고
> → 제일 중요한 간만 정확히 → 다음 사람이 읽을 레시피 → 혼자 해보기
