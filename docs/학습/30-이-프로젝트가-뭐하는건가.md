# MES 출하성적서 — 처음 보는 사람을 위한 가이드

> 이 문서 하나만 읽으면 **① 이게 뭐 하는 물건인지 ② 왜 이렇게 만들었는지 ③ "이거 고쳐주세요" 요청이 왔을 때 어느 파일을 열어야 하는지**를 알 수 있게 쓴다.
> 코드를 몰라도 읽을 수 있게 **학교 성적표 비유**로 설명한다.

---

## 0. 30초 요약

**공장에서 만든 물건이 "검사 통과했다"는 증명서를 뽑아주는 프로그램**이다.
그 증명서를 **출하성적서**, 영어로 **CoA** (Certificate of Analysis) 라고 부른다.

물건을 대기업에 납품할 때 "우리 제품 규격 맞습니다"를 종이로 증명해야 한다. 그 종이를 만드는 게 이 프로그램의 **최종 목표**다. 나머지 화면은 전부 그 종이 한 장을 위해 존재한다.

---

## 1. 학교 성적표로 바꿔 생각하기

MES 용어는 낯설지만, **학교 성적표와 구조가 똑같다.**

| 공장 용어 | 학교로 바꾸면 | 설명 |
|---|---|---|
| **Lot** (로트) | **학생 한 명** | 같은 조건에서 한 번에 만든 제품 묶음. "9월 4일 1호기에서 만든 브라켓 100개" = 학생 1명 |
| **검사항목** | **과목** | 인장강도, 경도, 불순물… = 국어, 수학, 영어 |
| **규격** (LSL~USL) | **합격 기준** | "400~500 MPa" = "60점 이상 합격" |
| **측정값** | **시험 점수** | 실제로 재본 값 |
| **판정** (PASS/FAIL) | **과목별 합격/불합격** | |
| **종합판정** | **진급 여부** | 한 과목이라도 떨어지면 진급 불가 |
| **출하성적서(CoA)** | **성적표** | 학부모(고객사)에게 보내는 공식 문서 |

> 🟢 그래서 이 프로그램은 **"공장 물건의 성적표를 만드는 학교 시스템"** 이라고 생각하면 됩니다.

---

## 2. 화면 5개가 왜 그 순서인가

성적표를 뽑으려면 **순서가 있다.** 시험 문제도 안 냈는데 성적표부터 뽑을 수는 없다.

```
F1 품질규격          "수학은 60점 이상 합격"  ← 시험 문제와 합격 기준을 정한다
   ↓
F2 검사실적          "철수 수학 75점"        ← 실제로 시험 보고 점수를 적는다
   ↓                                          (서버가 채점해서 합격/불합격 결정)
F3 성적서 발행        성적표 인쇄             ← 합격한 학생만 성적표가 나온다
   ↓
F4 품질피벗          반 전체 성적표          ← 여러 학생 점수를 한 표로 훑어본다

F0 공통코어          학교 공통 물품          ← 위 4개가 다 같이 쓰는 부품
```

**F1 → F2 → F3 순서는 바꿀 수 없다.** 규격이 없으면 채점을 못 하고, 채점이 없으면 성적표가 안 나온다.

**F4는 곁가지다.** 성적표를 뽑는 데 꼭 필요하진 않고, "우리 공장 요즘 품질 어때?"를 보는 화면이다.

**F0은 뿌리다.** 품목 고르는 콤보박스, 사용자 고르는 콤보박스 같은 걸 F1~F4가 전부 가져다 쓴다.

## 3. 데이터가 흐르는 길 (전체 숲)

```
 [사람]              [화면]                    [데이터]
                                          ┌──────────────────┐
 품질담당자  ──▶  F1 품질규격 등록  ──────▶ │ MST_INSP_SPEC    │  검사 규격
                                          │ (품목별 합격기준) │
                                          └────────┬─────────┘
                                                   │ 채점 기준으로 사용
                                                   ▼
 검사원      ──▶  F2 검사실적 입력  ──────▶ ┌──────────────────┐
                        │                  │ TRN_INSP_RESULT  │  측정값 + 판정
                        │  서버가 채점      │ TRN_LOT          │  Lot 상태
                        ▼                  └────────┬─────────┘
                  종합판정 계산                      │ 합격(OK)만
                  Lot 상태 전이                      ▼
                                          ┌──────────────────┐
 발행담당자  ──▶  F3 성적서 발행    ──────▶ │ TRN_COA          │  성적서 (사진처럼 고정)
                        │                  │ TRN_COA_DETAIL   │
                        ▼                  └──────────────────┘
                  브라우저 인쇄 → PDF

 관리자      ──▶  F4 품질피벗       ◀────── (위 데이터를 읽기만)
```

### Lot의 일생 (제일 중요한 그림)

```
  WAIT ──검사 시작──▶ INSP ──전 항목 합격──▶  OK   ──▶ 성적서 발행 가능 ✅
 검사대기            검사중      │           합격
                                │
                                └──1개라도 불합격──▶ LOCKED ──▶ 발행 불가 ❌
                                                    불합격
                                                       │
                                                       └─ 재검사해서 합격되면 다시 OK 로
```

> 🟢 **"불합격이면 끝"이 아닙니다.** 다시 재보고 합격이 나오면 자동으로 합격으로 돌아옵니다. 재시험 같은 거예요.

## 4. 이 프로젝트를 관통하는 원리 6개

코드 곳곳에 이 원리들이 박혀 있다. **이걸 모르면 "왜 이렇게 짰지?" 싶은 코드가 많다.**

### 원리 1 — 채점은 선생님(서버)이 한다

화면에서도 점수를 입력하는 순간 바로 합격/불합격을 보여준다. 그런데 **그 판정은 믿지 않는다.**
저장 버튼을 누르면 **서버가 처음부터 다시 채점해서** 그 결과를 저장한다.

> 🟢 **학생이 자기 답안지를 채점해봐도 됩니다. 근데 성적표에 올라가는 건 선생님이 매긴 점수예요.**
> 🔵 화면 JS는 우회할 수 있다(개발자 도구로 API 직접 호출). 서버가 다시 계산해야 DB에 남는 값이 신뢰 가능하다.

### 원리 2 — 안 본 과목이 있으면 "합격"이 아니다

5과목 중 4과목만 시험 봤고 다 100점이어도, **종합판정은 "합격"이 아니라 "미검사"** 다.

> 🟢 안 본 과목을 통과시킨 성적표가 나가면 안 되니까요.
> 🔵 `NONE` 을 `FAIL` 보다 **먼저** 본다. 미입력이 하나라도 있으면 전체가 `NONE`.

### 원리 3 — 딱 맞으면 합격이다

합격 기준이 "60점 이상"이면 **정확히 60점도 합격**이다. `>=` 이지 `>` 가 아니다.

> 🟢 "60점 이상"인데 60점 받은 애를 떨어뜨리면 안 되잖아요.
> 🔵 `<` 를 쓰면 규격에 딱 맞는 제품이 전부 불합격 처리된다. **이 프로젝트에서 가장 위험한 한 글자**다.

### 원리 4 — 성적표는 발행하는 순간 사진이 된다

성적표를 뽑은 뒤에 시험 문제나 합격 기준이 바뀌어도, **이미 나간 성적표는 안 바뀐다.**

> 🟢 사진을 찍어둔 것과 같아요. 나중에 머리를 잘라도 사진 속 머리는 그대로죠.
> 🔵 발행 시 규격·측정값·판정을 `TRN_COA_DETAIL` 에 **복사해서 저장**한다. 조회할 때 원본 테이블을 조인하지 않는다. 조인하면 과거 문서가 소급 변경된다.

### 원리 5 — 지우지 않고 쌓는다

재검사를 하면 이전 측정값을 **덮어쓰지 않는다.** 새 줄을 추가하고, 최신 줄에만 "최신" 표시를 단다.

> 🟢 재시험 봤다고 1차 점수를 지우진 않아요. 둘 다 남기고 "이게 최종"이라고 표시만 합니다.
> 🔵 `LATEST_YN='Y'` 인 행만 판정·성적서에 쓴다. "불합격 났다가 재측정으로 합격됐다"는 이력이 품질 추적의 핵심이다.

### 원리 6 — 서버 응답을 포장하지 않는다

서버가 목록을 주면 **목록 그대로** 준다. `{ 성공: true, 데이터: [...] }` 같은 상자에 담지 않는다.

> 🟢 택배 상자 안에 또 상자를 넣지 않는 거예요. 물건이 바로 나와야죠.
> 🔵 래핑하면 화면마다 `res.data.data` 를 벗겨야 하고, 백엔드에도 래퍼 객체가 생겨 No-DTO 원칙이 깨진다. 성공/실패는 HTTP 상태코드로 표현한다.

## 5. 파일 지도 — 어디에 뭐가 있나

```
mes/
├─ docs/                    📄 설계 문서 (여기)
│  ├─ 01-plan/              무엇을 만들지 (기획)
│  └─ 02-design/            어떻게 만들지 (설계) ← 코드의 근거가 전부 여기

└─ src/                     💻 실제 코드
```

## 6. 🔧 "이거 수정해주세요" → 어디를 만지나

**관리자 요청 유형별 대응표.** 이 표가 이 문서의 핵심이다.

### 🟩 코드를 안 고쳐도 되는 것 (화면에서 처리)

| 요청 | 하는 법 |
|---|---|
| "검사항목 하나 추가해주세요" | **F1 화면**에서 [행추가] → 저장 |

| "성적서 양식 바꿔주세요" | `components/CoaSheet.vue` | 표 구조·칸 이름 수정 |

| "에러 메시지 문구 바꿔주세요" | `api/http.js` (저장 관련) / `api/specValidator.js` (규격 입력) | 메시지 문자열 |
| "화면 제목·안내문 바꿔주세요" | 해당 `pages/*.vue` | `<template>` 안의 글자 |

### 🟥 위험 구역 — 고치기 전에 반드시 확인

| 요청 | 파일 | 왜 위험한가 |
|---|---|---|
| **"판정이 이상해요"** | `utils/specJudgeClient.js` | **여기 한 글자 틀리면 합격품이 전부 불합격으로 나갑니다.** 고치기 전에 반드시 테스트부터 |
| "종합판정 규칙 바꿔주세요" | `utils/specJudgeClient.js` 의 `total()` | 원리 2가 깨질 수 있음 |
| "발행 조건 바꿔주세요" | `api/http.js` 의 `coa-target-list` | 불합격품 성적서가 나갈 수 있음 |
| "성적서에 이 항목도 넣어주세요" | `api/http.js` 의 `buildCoaDetail()` | 필터를 잘못 풀면 **합격 성적서에 불합격 줄이 인쇄**됨 |
| 새 필드/새 API 추가 | `docs/02-design/` **먼저** → 그다음 코드 | 문서와 코드가 어긋나면 다음 사람이 못 따라옴 |

### 🟦 새 기능 추가는 3곳을 같이

새 조회 조건이나 새 버튼을 넣으려면 **최소 3개 파일**을 같이 고쳐야 한다.

```
1. pages/○○Page.vue     화면에 입력칸·버튼 추가
2. api/quality.js        서버 부르는 함수 추가
3. api/http.js           가짜 서버가 응답하도록 추가
   (+ 나중에 자바가 붙으면 3번 대신 자바 컨트롤러)
```

> 🟢 **주문서 → 창구 → 주방** 이 세 곳이 다 알아야 새 메뉴가 나옵니다.

## 7. 자주 나올 질문

### Q. 자바(백엔드)는 어디 있나요?
**아직 없습니다.** 일부러 그렇게 했습니다.

`api/http.js` 가 **자바인 척하는 가짜 서버**입니다. 화면이 제대로 도는지를 먼저 확인하고, 나중에 이 파일 안쪽만 진짜 서버 호출로 바꾸면 화면 코드는 **한 줄도 안 건드려도** 됩니다.

> 🟢 식당을 열기 전에 **주방 없이 홀부터 꾸며보는 것**과 같아요. 손님 동선이 되는지 먼저 봅니다.

### Q. 데이터를 고쳤는데 새로고침하면 돌아와요
정상입니다. 지금 데이터는 **메모리**에만 있습니다. 진짜 DB가 아직 없어서요.
원본은 `src/mock/*.json` 이고, 새로고침하면 거기서 다시 읽습니다.

### Q. 설계서에 붙은 `D27`, `D41` 같은 건 뭔가요?
**결정 번호**입니다. "이건 왜 이렇게 했지?" 싶을 때 그 번호로 문서를 검색하면 **이유가 적혀 있습니다.**

예: `D3` 은 "성적서 No. 열을 1부터 다시 매기는 이유"입니다 — 검사항목을 중간에 지우면 순번이 `1, 2, 5, 9` 처럼 띄엄띄엄해지는데, 성적서에 그렇게 찍히면 *"3번 4번은 어디 갔냐"* 는 질문을 받습니다.

### Q. RealGrid2는 왜 F4에서만 쓰나요?
상용 그리드는 **비싸고 무겁습니다.** 규격 등록 같은 단순 표에는 과합니다.
F4 품질피벗은 **컬럼 개수가 조회할 때마다 바뀌는** 화면이라 여기만 필요합니다.

### Q. 화면 주소가 안 바뀌는데요? (뒤로가기 안 됨)
`vue-router` 를 아직 안 넣었습니다. 화면 5개를 탭으로만 오가고 있습니다.
**URL 공유나 뒤로가기가 실제로 필요해지는 시점**(예: 성적서 링크 공유)에 넣습니다.
