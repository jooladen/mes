## 3. 판단 기준 7개 — 코드를 만나면 이렇게 읽는다

| # | 이런 게 보이면 | 뜻 | 어떻게 |
|---|---|---|---|
| 1 | `format~`, `to~`, `utils/` 안에 있음 | **포장지** — 값을 안 만든다 | 무시하고 지나감 |
| 2 | `defineProps` | **받기만 함** | 파일 밖에서 부모를 찾음 |
| 3 | **`await`** | ⭐ **국경** | 여기부터 서버 영역 |
| 4 | `api/` 폴더의 한 줄 함수 | **전화번호부** | 주소로 한 번 더 점프 |
| 5 | `x = 계산(...)` 후 저장 | ⭐ **굳힌 값** | 나중에 로직 고쳐도 과거는 안 변함 |
| 6 | `find(...)` `filter(...)` | **다른 테이블에서** | 연결고리(키)를 확인할 것 |
| 7 | `reduce` `sum` `* +` | **계산값** | DB에 없다 |

### 포장지를 알아보는 3가지 (셋 다 맞으면 확실)

- 이름이 `format~` / `render~` / `to~Text`
- 파일이 `utils/` 안
- **함수 안에 가져오는 코드가 없다** (fetch, api, DB 없음)

😖 여기서 *"찾았다!"* 하면 **포장지 공장 주소를 적어간 것.** 선물이 어디서 왔는지는 여전히 모른다.

## 4. 가공 7종 — 값은 이 중 하나로 만들어진다

| # | 가공 | 예 | 알아보는 법 |
|---|---|---|---|
| 1 | **안 함** | `orderDt` | `a: b.a` 그대로 |
| 2 | **다른 테이블에서** | `custNm` | `find` `filter` |
| 3 | **계산** | `amount` | `*` `+` |
| 4 | **합계** | `totalAmount` | `reduce` |
| 5 | **번호 다시** | `printSeq` `printNo` | `++` 카운터 |
| 6 | **모양만 바꿈** | `55,000` | `format~` `toLocaleString` |
| 7 | **굳혀둠** ⭐ | `unitPrice` `totalJudge` | 저장할 때 계산해 박아둠 |

### ➕ 어디서 가공했나도 봐야 한다

```
DB(SQL)   →   서버(자바)   →   화면(JS)
   ①             ②              ③
```

😖 *"합계가 틀려요"* 를 듣고 **자바를 3시간 뒤졌는데 화면에서 더하고 있었다** — 실제로 흔한 사고.
🟢 **김밥이 짜다.** 밥에 소금? 속재료? 위에 뿌렸나? **어디서 짜졌는지 알아야 고친다.**

## 5. ⭐ 왜 MES는 어렵고 거래명세서는 쉬웠나

> 실습 중 준이 스스로 발견한 것. **난이도 차이 = 파일 구조 차이.**

### 실측 비교

| | MES 성적서 | 거래명세서 |
|---|---|---|
| 파일 수 | **11개** | **3개** |
| 거쳐가는 층 | **4단계** | **2단계** |
| 첫 문제 왕복 | **8회** | **4회** |
| 중간에 있던 것 | 포장지 함수 / `defineProps` / **전화번호부 층** | 없음 |

### 경로를 나란히 놓으면

```
[ MES ]  화면 → 컴포넌트 → 페이지 → 전화번호부(quality.js) → 서버(http.js) → DB
              └─ 포장지 ─┘         └─ 여기서 두 번 막힘 ─┘

[ 명세서 ] 화면 → api → seed → DB
```

**MES는 중간에 두 층이 더 있었다.** 그게 어려움의 정체다.

### 🟢 원룸과 아파트

| | 원룸 (파일 3개) | 방 5개 아파트 (파일 11개) |
|---|---|---|
| **찾기** | 😀 다 보임 | 😖 돌아다녀야 함 |
| **고치기** | 😖 요리하면 옷에 냄새 밤 | 😀 방마다 독립 |
| **둘이 살기** | 😖 부딪힘 | 😀 각자 방 |

> ## **파일을 쪼개면 — 고치기는 쉬워지고, 읽기는 어려워진다.**

**공짜가 아니다.** 둘 다 좋게는 안 된다.

### 그럼 MES는 왜 쪼갰나

| 이유 | 설명 |
|---|---|
| 화면이 **5개** | 판정 로직을 3개 화면이 같이 씀 → 한 곳에 두어야 함 |
| **자바로 교체 예정** | `http.js` 하나만 바꾸면 화면 5개는 안 건드림 |
| **테스트** | 계산 로직만 따로 검사하려면 화면과 분리돼야 함 |

명세서는 **화면 1개 / 혼자 / 교체 계획 없음** → 쪼갤 이유가 없었다.

### 📌 언제 쪼개나 — 판단표

| 상황 | 판단 |
|---|---|
| 화면 1~2개, 혼자, 100줄 | ❌ **쪼개지 마라** |
| **바뀌는 이유가 2개 이상 보임** | ⭐ **지금 쪼개라** |
| 여러 화면이 같은 로직을 씀 | ✅ 쪼개라 |
| 나중에 백엔드를 갈아끼울 예정 | ✅ 쪼개라 |
| 300줄 넘음 | 검토 |

> 😀 **"나중에 쪼개야지"는 괜찮다. "미리 쪼개놓자"가 위험하다.**
> 안 쪼개서 겪는 고통은 나중에 고칠 수 있지만, **잘못 쪼개면 되돌리기가 더 어렵다.**

### 세 파일이 갈린 기준 — 바뀌는 날이 다르다

| 파일 | 언제 바뀌나 | 누가 시키나 |
|---|---|---|
| `OrderPage.vue` | **모양**이 바뀔 때 | 현업 / 디자이너 |
| `ordersApi.js` | **계산·규칙**이 바뀔 때 | 현업 |
| `orderSeed.js` | **데이터·DB**가 바뀔 때 | DBA |

**셋은 같은 날 안 바뀐다.** 그래서 갈랐다.

### 방향은 한쪽뿐

```
OrderPage.vue  →  ordersApi.js  →  orderSeed.js
     ─────────── 아는 방향 ───────────→
```

**데이터가 화면을 알면 안 된다.** 알면 화면 하나 고칠 때마다 데이터 코드를 건드리게 된다.

### 고칠 게 생기면 — 이 세 줄만 기억

```
모양   고칠 땐 → 화면 파일
계산   고칠 땐 → api 파일
데이터 늘릴 땐 → seed 파일 (실무에선 DB)
```

## 6. 🚨 오늘 걸린 함정 — 박제된 값

### 무슨 일이 있었나

거래명세서에서 **A4용지 단가가 명세서마다 달랐다** (3,000 / 3,200).
품목 마스터엔 **3,200 하나뿐**이었다.

**판단:** *"마스터가 정답이니 주문 상세의 `unitPrice` 를 없애고 마스터를 보게 하자."*

### 실행하면

```
[9월 5일 명세서]  합계  55,000   ← 고객이 입금한 금액
     ↓ 수정 후 다시 열면
                  합계  57,000   ← 🚨 오늘 가격으로 계산됨
```

**지난 3년치 명세서가 전부 오늘 가격으로 바뀐다.** 세금계산서와 안 맞는다.

### 🟢 영수증

작년 영수증에 우유 2,000원. 지금 우유는 2,500원.
**영수증을 다시 뽑으면 2,500원이 찍혀야 하나? 아니다.**
영수증은 **그때 그 순간을 박제한 것**이다.

### 중복이 아니었다 — 이름만 같았다

| 어디 | 뜻 |
|---|---|
| `MST_ITEM.UNIT_PRICE` | **지금 파는 값** (내일 바뀔 수 있음) |
| `TRN_ORDER_DETAIL.UNIT_PRICE` | ⭐ **그때 판 값** (영원히 안 바뀜) |

### 🔍 알아보는 패턴

```
같은 이름의 컬럼이  MST_(마스터)  와  TRN_(거래)  양쪽에 있다
                          ↓
              🚨 거의 항상 "박제된 값". 손대지 마라.
```

| 마스터 | 거래 | 왜 박제하나 |
|---|---|---|
| `MST_ITEM.UNIT_PRICE` | `TRN_ORDER_DETAIL.UNIT_PRICE` | 판 가격 보존 |
| `MST_CUSTOMER.CUST_NM` | `TRN_COA_HEADER.CUST_NM` | 상호가 바뀌어도 옛 문서는 그대로 |
| `MST_EMP.EMP_NM` | 발행자명 | 퇴사자 이름 보존 |

### MES에서도 같은 것을 봤다

```
lot.totalJudge = total(perSpec)     ← 검사 저장할 때 계산해서 박아둠
      ↑ 소속 API: inspect-save (성적서 발행이 아니다)
```

😖 **판정 로직을 고쳐도 기존 Lot은 안 바뀐다.** 이미 박혀 있으니까.
*"고쳤는데 왜 안 바뀌죠?"* 로 반나절이 간다.

## 7. 코드가 알려주는 것 / 못 알려주는 것

| | 어디서 아나 |
|---|---|
| **무엇을** 하는지 (What) | ✅ **코드** — 거짓말 안 함 |
| **왜** 그렇게 했는지 (Why) | ❌ 코드에 없음 → **사람에게 물어야** |

함정에 걸린 이유가 이거였다. **코드는 정확히 읽었다.** `unitPrice` 가 두 곳에 있는 건 사실이다.
**모른 건 "왜"였고, 그건 코드에 안 적혀 있었다.**

### 📌 이 질문 하나가 3년치 데이터를 지킨다

> *"이 단가, 주문할 때 값으로 굳혀두는 건가요? 아니면 항상 최신 가격인가요?"*

**5초짜리 질문이다.**

### 순서

```
① 코드로 30분 훑는다   → ❓ 가 줄어든다
② 남은 ❓ 만 사람에게   → 짧고 정확한 질문이 된다
```

😖 순서를 바꾸면 — *"이 시스템이 뭐 하는 건가요?"* 같은 큰 질문을 하게 되고, **1시간 강의를 듣고 아무것도 안 남는다.**

## 8. 그 외 오늘 확인한 것들

### 값이 아니라 칸을 쫓는다

| | 바뀌나? |
|---|---|
| **테이블·컬럼** (`TRN_ORDER.ORDER_DT`) | ❌ 안 바뀜 |
| **값** (`2026-09-05` / `09-04`) | ✅ 고른 행마다 바뀜 |

🟢 **우편함 번호는 그대로, 안에 든 편지는 매일 바뀐다.** 우리가 찾는 건 **우편함 번호**다.

📌 **실무 습관:** 문제 제보를 받으면 제일 먼저 **"어느 건이요?"** 를 묻는다. 번호를 받아야 재현이 된다.

### 이름은 두 개다

| | 예 | 어디서 쓰나 |
|---|---|---|
| 코드 이름 | `orderTable` `orderDt` | 개발자끼리, JS 안 |
| **테이블·컬럼명** | `TRN_ORDER` `ORDER_DT` | **DB, SQL, DBA와 대화** |

카멜 ↔ 스네이크 변환: `custNm` ↔ `CUST_NM`, `totalAmount` ↔ `TOTAL_AMOUNT`
😀 화면에서 `custNm` 을 보면 **DB는 `CUST_NM` 이겠구나**가 90% 맞는다.

😖 *"DBA님, orderTable 조회해주세요"* → *"그런 테이블 없는데요?"* — **SQL은 코드 변수명을 모른다.**

### 마스터-디테일 (머리 + 몸통)

```js
{
  orderNo, orderDt, custNm, totalAmount,   ← 머리 : 딱 1벌
  detailList: [ {...}, {...}, {...} ]      ← 몸통 : 항목 수만큼
}
```

🟢 **영수증** — 위쪽(가게·날짜·총액)은 한 번, 아래쪽(산 물건)은 여러 줄.

| 업무 | 머리 | 몸통 |
|---|---|---|
| 거래명세서 | 명세서번호·거래처 | 품목들 |
| 출하성적서 | Lot·품목·종합판정 | 검사항목들 |
| 급여명세서 | 사번·지급월 | 수당·공제 |

😀 새 화면을 처음 봐도 **"위가 머리, 아래가 몸통"** 하고 5초에 구조를 잡는다. 그럼 *"머리는 어느 테이블? 몸통은?"* 두 개만 물으면 끝난다.

### 화면 문제는 3방향

| 요청 | 방향 | 어디를 파나 |
|---|---|---|
| *"이 금액 왜 이래요?"* | **조회** | 조회 API → 가공 코드 |
| *"저장이 안 돼요"* | **저장** | 저장 API → 검증 코드 |
| *"버튼이 안 눌려요"* | **화면만** | DB 근처도 안 감 |

😖 *"저장이 안 돼요"* 를 듣고 **조회 쿼리를 3시간 뒤진다.**

### 조인은 연결고리를 확인한다

```
orderTable                    custTable
custCd: 'C001'  ────────→   custCd: 'C001' → custNm
                  ⭐ 연결고리
```

😖 연결고리를 틀리면 SQL이 **에러도 없이 빈 결과**를 낸다. 그래서 더 무섭다.
