## 1. Overview

### 1.1 Purpose

발행 가능한 Lot을 선택해 **출하성적서를 자동 조립·미리보기·인쇄**하고, 발행 사실을 이력으로 남긴다.

### 1.2 Background

이 문서는 **회사 밖으로 나간다.** 사내 화면과 요구 수준이 다르다.

- 값이 틀리면 안 된다 → F2 저장값을 그대로 써야 하고, 여기서 재계산하면 안 된다
- 양식이 흔들리면 안 된다 → 인쇄 시 줄 밀림·페이지 잘림이 없어야 한다
- 발행 기록이 남아야 한다 → 누가 언제 무엇을 발행했는지

**발행 대상 제한이 핵심 규칙이다.** F2에서 잠긴(불합격) Lot과 검사 미완료 Lot은 **목록에 아예 나오지 않아야** 한다. 발행 버튼을 눌렀을 때 막는 게 아니라, 고를 수 없어야 한다.

### 1.3 마스터플랜에서 확정된 양식

```
┌──────────────────────────────────────────────────────┐
│              출 하 성 적 서 (CoA)                     │
├───────────────┬──────────────┬───────────────────────┤
│ 성적서번호     │ 발행일자      │ 고객사                 │  ← 헤더
│ 품목코드/품명  │ Lot No.      │ 출하수량               │
├───────────────┴──────────────┴───────────────────────┤
│ No │ 검사항목 │ 단위 │ 규격(LSL~USL) │ 측정값 │ 판정  │  ← 본문(N행)
│  1 │ 인장강도 │ MPa  │ 400 ~ 500     │ 452   │ PASS │
├──────────────────────────────────────────────────────┤
│ 종합판정: PASS            발행자: ____  (인)          │  ← 푸터
└──────────────────────────────────────────────────────┘
```

| 시점 | 헤더 | 본문 | 종합판정 |
|------|------|------|---------|
| **발행 전** (미리보기) | `TRN_LOT` + `MST_ITEM` | `TRN_INSP_RESULT` ⋈ `MST_INSP_SPEC` (`sortNo` 순) | `TRN_LOT.TOTAL_JUDGE` |
| **발행 후** (재조회·인쇄) | `TRN_COA` | **`TRN_COA_DETAIL`** (발행시점 스냅샷) | `TRN_COA.TOTAL_JUDGE` |

⚠️ **발행 후에는 `MST_INSP_SPEC`·`TRN_INSP_RESULT` 를 보지 않는다** (Design §3 스냅샷 확정 — N13). 종합판정도 **여기서 재계산하지 않는다** (FR-06).

## 2. Scope

### 2.1 In Scope

- [ ] 발행 가능 Lot 목록 조회 — 검사완료 + 합격 Lot만
- [ ] Lot 선택 시 성적서 데이터 조회 (헤더 + 본문 + 종합판정)
- [ ] 성적서 양식 미리보기 화면
- [ ] 인쇄 / PDF 저장
- [ ] 성적서 번호 자동 채번
- [ ] 발행 이력 저장 (`TRN_COA` — 발행자, 발행일시, 고객사)
- [ ] 재발행 — 같은 Lot 재발행 시 이력이 누적된다
- [ ] 테이블 정의 — `TRN_COA`, **`TRN_COA_DETAIL`** (발행시점 본문 스냅샷)

### 2.2 Out of Scope

- 고객사별 커스텀 양식 (단일 표준 양식만)
- **고객사 마스터(`MST_CUST`) 및 Lot-고객사 자동 귀속** — Sprint-1은 발행 시 직접 입력(FR-12). 마스터 연계는 carry item
- 전자서명 / 직인 이미지 삽입
- 이메일 자동 발송, 고객 포털 업로드
- 다국어 성적서 (영문 CoA)

### 2.3 ~~결정 필요~~ **Design에서 확정 완료**

| 항목 | 선택지 | 권장 |
|------|-------|------|
| ~~출력 방식~~ | ~~ⓐ 브라우저 인쇄 ⓑ 서버 PDF~~ | **확정: ⓐ 브라우저 인쇄** (design §5) |
| ~~규격 스냅샷~~ | ~~ⓐ 복사 저장 ⓑ 현재값 조인~~ | **확정: ⓐ 스냅샷** → `TRN_COA_DETAIL` 신설 (data-model §3.9) |

> ⚠️ 두 번째 항목이 중요하다. ⓑ로 가면 **작년에 발행한 성적서를 오늘 다시 열었을 때 규격이 달라져 있을 수 있다.** F1이 Spec 이력을 관리하지 않기 때문이다. Design에서 반드시 결론 낼 것.

## 3. Requirements

### 3.1 Functional Requirements

| ID | 요구사항 | 우선순위 | 상태 |
|----|---------|--------|------|
| FR-01 | 검사 완료 + 종합판정 PASS 인 Lot만 발행 목록에 표시된다 | High | Pending |
| FR-02 | 잠긴(FAIL) Lot과 미완료 Lot은 목록에 나타나지 않는다 | High | Pending |
| FR-03 | Lot 선택 시 성적서 미리보기가 확정 양식으로 표시된다 | High | Pending |
| FR-04 | 본문 검사항목은 F1의 정렬번호 순으로 출력된다 | High | Pending |
| FR-05 | 규격 열은 판정방식에 따라 표기가 달라진다 (`400 ~ 500` / `≤ 0.5` / `≥ 99.5`) | High | Pending |
| FR-06 | 종합판정은 F2 저장값을 그대로 표시한다 (재계산 금지) | High | Pending |
| FR-07 | 인쇄 시 표가 잘리거나 줄이 밀리지 않는다 | High | Pending |
| FR-08 | 성적서 번호가 규칙에 따라 자동 채번된다 | High | Pending |
| FR-09 | 발행 시 `TRN_COA` 에 이력이 저장된다 (발행자·일시·고객사) | High | Pending |
| FR-10 | 같은 Lot을 재발행하면 이력이 누적되고 새 번호가 부여된다 | Medium | Pending |
| FR-11 | 검사항목이 많아 여러 페이지가 되면 각 페이지에 헤더가 반복된다 | Medium | Pending |
| FR-12 | **발행 화면에서 고객사명과 출하수량을 직접 입력**하고, 입력값이 성적서 헤더와 발행 이력에 저장된다 | High | Pending |

### 3.2 Non-Functional Requirements

| 구분 | 기준 | 측정 방법 |
|------|------|----------|
| 속도 | Lot 선택 → 미리보기 표시 1초 이내 | 육안/네트워크 탭 |
| 정확성 | 표시값이 F2 저장값과 100% 일치 | DB 값 대조 |
| 인쇄 품질 | A4 1페이지 기준 여백·잘림 없음 | 실제 인쇄 미리보기 |

## 4. Success Criteria

### 4.1 Definition of Done

- [ ] FR-01 ~ FR-12 구현
- [ ] **관통 시연**: Lot 선택 → 미리보기 → PDF 출력, 중단 없음
- [ ] 표시된 측정값·판정이 F2 저장값과 전부 일치
- [ ] FAIL Lot이 목록에 없음을 확인
- [ ] 인쇄 미리보기에서 표 잘림 없음 (검사항목 15건 기준)

### 4.2 Quality Criteria

- [ ] 성적서 데이터 조회가 단일 API 호출로 완결 (헤더+본문 분리 호출 금지)
- [ ] DTO 0개, `ResponseEntity` 0건
- [ ] 빌드 에러 0건

## 5. Risks and Mitigation

| 위험 | 영향 | 가능성 | 대응 |
|------|------|-------|------|
| 성적서 값이 실제 검사 결과와 불일치 → 대외 신뢰 사고 | **High** | 低 | FR-06 — 재계산 금지, F2 저장값 직접 사용. 시연 시 DB 대조 |
| 불합격 Lot의 성적서가 발행됨 | **High** | 中 | FR-01·02 — 목록 단계에서 원천 차단 (버튼 비활성화가 아니라 목록 제외) |
| Spec 변경으로 과거 성적서 내용이 소급 변경 | **High** | 中 | §2.3 규격 스냅샷 결정을 Design에서 확정 |
| 브라우저별 인쇄 여백 차이로 양식 깨짐 | Medium | **High** | `@media print` CSS를 Chrome 기준으로 고정하고 실제 인쇄 미리보기로 검증 |
| 항목 수가 많을 때 페이지 분할 실패 | Medium | 中 | FR-11 — 15건 기준으로 사전 검증 |
