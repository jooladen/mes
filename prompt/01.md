# MES Phase 1 (출하성적서/CoA 중심) 풀스택 통합 구축 지시서

## 1. 아키텍처 및 코딩 원칙 (Architectural Rules)
1. **No JPA, Only MyBatis:** ORM(JPA, Hibernate) 사용을 엄격히 금지한다. DB 퍼시스턴스 레이어는 오직 MyBatis만 사용한다.
2. **No DTO, Pure CamelMap:** 백엔드 전체(Controller - Service - Mapper)에서 DTO 클래스를 생성하지 않는다. 모든 Request Parameter 및 Response Result는 MyBatis의 CamelCase 자동 변환 Map (`CamelMap`) 객체만 사용한다.
3. **No ResponseEntity:** Spring Controller에서 `ResponseEntity` wrapping을 사용하지 않는다. Pure `CamelMap` 또는 `List<CamelMap>`을 직접 반환하여 컨트롤러 구성을 최소화한다.
4. **DB Agnostic Architecture (Mock -> SQLite -> Oracle):**
   - [1단계: Mock Service] -> [2단계: SQLite MyBatis] -> [3단계: Oracle MyBatis]로 손쉽게 전환할 수 있도록 구현한다.
   - Controller 및 Service 인터페이스는 특정 DB나 SQL에 완벽히 독립적으로 유지한다.
   - `@Profile("mock")` / `@Profile("mybatis")` 스위칭 구조로 작성하고, 우선 DB 연결 없이 즉시 동작 가능한 **Mock Service 구현체**를 주력으로 구성한다.
5. **No SQL Concatenation (`||` 사용 금지):**
   - DB 쿼리에서 `DEPTCD || '|' || DEPTNM` 등 문자열 결합 연산을 절대 수행하지 않는다.
   - 백엔드는 `{ deptCd: '0000', deptNm: '개발부' }` 형태의 Pure JSON/Map만 반환하고, UI 표현은 Vue3/Quasar Template Slot에서 100% 핸들링한다.

## 2. 백엔드 구현 사양 (Spring Boot + MyBatis)

1. **`CamelMap` 구현 및 공통 설정:**
   - Apache Commons `ListOrderedMap` 또는 `CamelCaseMap`을 상속받아 MyBatis 결과 매핑용 `CamelMap` 클래스를 구현한다.
   - Spring Boot / MyBatis 설정에 `mapUnderscoreToCamelCase=true` 및 `CamelMap` TypeAlias를 세팅한다.
2. **REST Controller 샘플 코드:**
   - 아래 API 항목들을 Pure `CamelMap` 반환 구조로 작성한다.
     - `POST /api/common/dept-list` : 부서 목록 조회
     - `POST /api/quality/coa-spec` : 출하성적서 Spec 기준정보 조회
     - `POST /api/quality/coa-result` : 검실적 및 출하성적서 Auto Pass/Fail 데이터 조회
3. **Mock 데이터 서비스 구현:**
   - DB 연결 없이 프론트엔드 테스트가 즉시 가능하도록 `@Profile("mock")` 기반 가짜 데이터 리턴 서비스 클래스를 작성한다.
   - 추후 SQLite 및 Oracle 전환 시, MyBatis Mapper XML에서 동적 쿼리(`concat`, `sysdate` 등 DB 방언) 수용을 위한 가이드를 주석으로 명시한다.

## 3. 프론트엔드 구현 사양 (Vue3 script setup + Quasar)

백엔드에서 받은 `CamelMap` 객체(`{ deptCd: '0000', deptNm: '개발부' }`)를 직접 바인딩하는 3가지 공통 UI 컴포넌트를 작성한다.

1. **`DeptSelect.vue` (부서 선택 커스텀 콤보):**
   - Quasar `q-select` 기반. 백엔드의 `deptCd`, `deptNm`을 Scoped Slot으로 분리 렌더링.
   - 선택 완료 바(Selection Slot): `개발부 | 0000` 형태 (부서명 Bold, 코드명 Captioned/Badge).
   - 드롭다운 목록(Option Slot): 좌측 `부서명`, 우측 `[코드]` 배지 형태.

2. **`MultiCheckCombo.vue` (멀티 체크 콤보):**
   - Quasar `q-select` 기반, `multiple`, `use-chips` 옵션 적용.
   - Option 슬롯 내부에 `q-checkbox`를 매핑하여 항목별 체크박스 다중 선택 처리.

3. **`MultiTreeCombo.vue` (멀티 트리 콤보):**
   - Quasar `q-select`의 `v-slot:popup-content` 내부에 `q-tree` 컴포넌트를 중첩.
   - 계층 구조(조직/공정 트리) 데이터를 체크박스로 다중 선택하고, 상단 콤보박스에 Chip으로 결과 바인딩.
