# MES Phase 1 & Phase 2 전체 풀스택 통합 구축 지시서

## 1. 아키텍처 및 코딩 원칙 (Architectural Rules)
1. **No JPA, Only MyBatis:** ORM(JPA, Hibernate) 사용을 엄격히 금지한다. DB 퍼시스턴스 레이어는 오직 MyBatis만 사용한다.
2. **No DTO, Pure CamelMap:** 백엔드 전체(Controller - Service - Mapper)에서 DTO 클래스를 생성하지 않는다. 모든 Request Parameter 및 Response Result는 MyBatis의 CamelCase 자동 변환 Map (`CamelMap`) 객체만 사용한다.
3. **No ResponseEntity:** Spring Controller에서 `ResponseEntity` wrapping을 사용하지 않는다. Pure `CamelMap` 또는 `List<CamelMap>`을 직접 반환하여 컨트롤러 구성을 최소화한다.
4. **DB Agnostic Architecture (Mock -> SQLite -> Oracle):**
   - [1단계: Mock Service] -> [2단계: SQLite MyBatis] -> [3단계: Oracle MyBatis]로 손쉽게 전환할 수 있도록 구현한다.
   - Controller 및 Service 인터페이스는 특정 DB나 SQL에 완벽히 독립적으로 유지한다.
   - `@Profile("mock")` / `@Profile("mybatis")` 스위칭 구조로 작성하고, 우선 DB 연결 없이 즉시 동작 가능한 **Mock Service 구현체**를 주력으로 구성한다.
5. **No SQL Concatenation (`||` 사용 금지):**
   - DB 쿼리에서 `DEPTCD || '|' || DEPTNM` 등 문자열 결합 연산을 절대 수행하지 않는다.
   - 백엔드는 `{ deptCd: '0000', deptNm: '개발부' }` 형태의 Pure JSON/Map만 반환하고, UI 표현은 Vue3/Quasar Template Slot에서 100% 핸들링한다.

## 2. 전체 기능 로드맵 및 핵심 화면 (Functional Requirements)

### [Phase 1: 출하성적서/품질 중심 모듈]
1. **품목별 품질 Spec 관리 화면:** 품목(Item)별 검사 항목, 검사 기준치(USL/LSL), 단위, 판정 방식 정의.
2. **공정 및 최종 검사 실적 등록 화면 (Quasar POP UI):** Lot 번호 기준 측정값 입력, Spec 범위 오차 자동 판정(Auto Pass/Fail) 및 초과 시 Alert/Locking 처리.
3. **출하성적서(CoA) 자동 생성 및 인쇄 화면:** Lot 선택 시 검사 실적과 Spec 기준치를 조인하여 출하성적서 양식 레이아웃으로 변환. 1초 만에 PDF 출력/인쇄 기능 제공.
4. **RealGrid2 기반 품질 이력/Pivot 분석 화면:** 기간별 Lot 검사 측정값 Dynamic Pivot 뷰. Spec 이탈 데이터 셀 배경색 Red 하이라이트 및 Excel Export.

### [Phase 2: 현장 실행 & MES 풀스펙 확장 모듈]
1. **작업지시(WO) 및 공정 진행(Start/End) 제어 화면:** ERP 연동 작업지시 수신, 공정별(Routing) 착수/완료 처리, 공정 상태 Machine(대기->진행->완료->중단) 제어.
2. **자재 투입(Kitting) 및 실시간 BOM 차감 화면:** BOM 기준 소요량 계산, Kitting 바코드 스캔, 작업 완료 시 재공(WIP) 및 자재 실시간 차감(Backflushing).
3. **Lot Tracking (분할/합병/추적성) 관제 화면:** 원자재 Lot -> 공정 Lot -> 최종 제품 Lot 계층 구조 관리. RealGrid2 TreeGrid 기반 Top-Down / Bottom-Up 360도 이력 추적.
4. **설비 비가동 관리 및 OEE(설비종합효율) 분석 화면:** 비가동 사유 코드 등록, 비가동 시간 집계, OEE 계산(가동률 x 성능효율 x 양품률) 시각화 Dashboard.

## 3. 백엔드 구현 사양 (Spring Boot + MyBatis)

1. **`CamelMap` 구현 및 공통 설정:**
   - Apache Commons Map 기반 `CamelMap` 구현체 작성 및 MyBatis `mapUnderscoreToCamelCase=true` 세팅.
2. **REST Controller API (Pure CamelMap / List<CamelMap> 직접 반환):**
   - `POST /api/common/dept-list` : 부서 목록 조회
   - `POST /api/quality/spec-list` : 품목별 Spec 기준정보 조회
   - `POST /api/quality/inspect-save` : 검사 실적 저장 및 Auto Pass/Fail 처리
   - `POST /api/quality/coa-print-data` : 출하성적서 생성용 데이터 조회
   - `POST /api/production/work-order-list` : 작업지시 목록 및 공정 진행 상태 조회
   - `POST /api/production/process-start` : 공정 착수(Start) 및 자재 validation
   - `POST /api/production/process-end` : 공정 완료(End) 및 실적 저장
   - `POST /api/traceability/lot-tree` : Lot 계층형 이력 데이터 조회
3. **Mock 데이터 서비스 & DB 전환 가이드:**
   - DB 연결 없이 작동하는 `@Profile("mock")` 가짜 데이터 서비스 구현.
   - 추후 SQLite/Oracle 전환 시 MyBatis Mapper XML 작성 유의사항 주석 명시.

## 4. 프론트엔드 구현 사양 (Vue3 script setup + Quasar + RealGrid2)

백엔드에서 받은 `CamelMap` 객체(`{ deptCd: '0000', deptNm: '개발부' }`)를 직접 바인딩하는 3가지 공통 UI 컴포넌트 및 연동 화면을 작성한다.

1. **`DeptSelect.vue` (부서 선택 커스텀 콤보):**
   - 백엔드의 `deptCd`, `deptNm`을 Scoped Slot으로 분리 렌더링.
   - Selection Slot: `개발부 | 0000` (부서명 Bold, 코드명 Captioned/Badge).
   - Option Slot: 좌측 `부서명`, 우측 `[코드]` 배지.
2. **`MultiCheckCombo.vue` (멀티 체크 콤보):**
   - Quasar `q-select` 기반, `multiple`, `use-chips` 옵션 및 `q-checkbox` 다중 선택.
3. **`MultiTreeCombo.vue` (멀티 트리 콤보):**
   - Quasar `q-select` 팝업 내부에 `q-tree` 중첩하여 계층 구조 다중 선택 및 Chip 바인딩.
4. **RealGrid2 연동 화면:**
   - Lot 이력 추적용 **RealGrid2 TreeGrid** 레이아웃.
   - 품질 검사 수치 Spec 이탈 시 **조건부 서식(Red 색상) 및 Pivot View** 레이아웃.
